# Strudel AI Composer

Веб-приложение: вы описываете музыку словами, AI-агент генерирует код на [Strudel](https://strudel.cc/) (live-coding музыкальный фреймворк), и код сразу исполняется в браузере с визуализацией партий.

- **Текст → код** — LLM генерирует Strudel-код со стримингом (эффект живой печати)
- **Музыкальный разбор** — код измеряется по объективным метрикам (темп, плотность, грув, лад, диапазон, регистры) и получает оценку 0–100 с прозрачным разбором по критериям
- **Обратная связь** — «✨ Улучшить по разбору»: модель переписывает трек под конкретные замечания («темп 90 при цели 124–142», «мало атак», «бас и мелодия в одной октаве»)
- **Варианты A/B** — best-of-N: несколько вариантов под разными углами, каждый с оценкой, лучший — сверху
- **Живая партитура** — под каждой `$PART:` крупный пианоролл или осциллограф, с кодом партии над ним
- **Исполнение** — `@strudel/web`: звук сразу после генерации
- **Микшер** — громкость, mute и solo по каждой партии, живые индикаторы уровня
- **Правки по описанию** — «✨ Улучшить» показывает diff и применяет его после подтверждения
- **Голос** — необязательный ввод голосом (Groq Whisper); без ключа кнопка скрыта
- **Пресеты и история** — шесть встроенных пресетов, история генераций, экспорт/импорт, ссылка на трек
- **Дизайн** — тёмно-нефритовый (jade) по умолчанию, альтернативная тема obsidian, без UI-библиотек
- **Сэмплы** — `dirt-samples` (bd, sd, hh, cp, 808*, breaks* …) и `shabda:piano`; подгружаются сами, имена — без `.bank(...)`

Подробно о разборе и цикле обратной связи — [docs/MUSIC-ANALYSIS.md](docs/MUSIC-ANALYSIS.md).
Английская версия README — [README.en.md](README.en.md).

## Установка

```bash
npm install
cp .env.example .env   # вставьте свои ключи
npm run dev
```

Откроется `http://localhost:5173`. При первом клике разблокируется звук (политика браузеров для AudioContext).

## API-ключи

| Переменная | Где получить | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | https://platform.openai.com/api-keys | генерация Strudel-кода |
| `OPENAI_MODEL` | — | модель генерации |
| `OPENAI_BASE_URL` *(необязательно)* | совместимый прокси | если регион блокирует api.openai.com |
| `OPENAI_FALLBACK_MODEL` *(необязательно)* | — | резервная модель, если основная недоступна |
| `GROQ_API_KEY` *(необязательно)* | https://console.groq.com/keys | транскрипция голоса; без него кнопка микрофона скрыта |
| `OLLAMA_MODEL` *(необязательно)* | — | локальный инференс без интернета и оплаты |
| `ANTHROPIC_API_KEY` *(необязательно)* | https://console.anthropic.com | ещё один провайдер в роутере |

Провайдеры перебираются по порядку `LLM_PROVIDERS` (по умолчанию `openai`):
если текущий недоступен, запрос уходит следующему. Доступны `openai`, `groq`,
`ollama`, `anthropic` — OpenAI-совместимые и Anthropic Messages API.

Ключи используются только на стороне сервера: запросы идут через прокси Vite (`/api/generate` → LLM), на фронтенд не попадают.

## Как пользоваться

1. Опишите музыку в поле «Команда» и нажмите «▶ Сгенерировать»
2. «🎼 Разобрать» — оценить трек по объективным метрикам и увидеть, что мешает
3. «✨ Улучшить по разбору» — модель перепишет трек под замечания; показывается «было → стало»
4. «🎲 Варианты A/B» — три варианта под разными углами, каждый с оценкой; лучший сверху
5. «✨ Улучшить» — описать правки к текущему треку, показать diff и применить
6. Панель «Код Strudel» редактируема: правьте вручную и жмите «▶ Играть этот код»
7. Микшер справа: M — заглушить партию, S — solo, ползунок — громкость
8. 🎤 рядом с промптом — записать голосовое описание (нужен `GROQ_API_KEY`); автоотправки нет

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Space` | play / stop |
| `Ctrl` + `Enter` | сгенерировать трек |
| `Ctrl` + `S` | сохранить пресет |

### Примеры команд

- «драм-партия в стиле Queen с мощным басом»
- «спокойная мелодия на пианино в тональности ля минор, 80 BPM»
- «добавь к текущему коду хай-хэты на каждую восьмую»
- «сделай бас тяжелее и замедли темп»

## Структура

```
├── index.html                 # разметка: три колонки + транспорт
├── src/
│   ├── main.js                # точка входа
│   ├── ui.js                  # кнопки, лог, стриминг, горячие клавиши, тема
│   ├── editor.js              # подсветка синтаксиса, текущая строка, активная партия
│   ├── strudel-engine.js      # initStrudel, evaluateCode, stop, reset, unlockAudio
│   ├── pianoroll.js           # нефритовые пианороллы и осциллографы
│   ├── meters.js              # живые уровни партий (onTrigger) и их вплетение в код
│   ├── live.js                # связь метров с микшером, визуализациями и редактором
│   ├── mixer.js               # каналы, fader, mute/solo
│   ├── transport.js           # play/stop, BPM, тональность, запись
│   ├── history.js             # пресеты и история
│   ├── improve.js             # режим «улучшить» с diff
│   ├── music-panel.js         # панель музыкального разбора: оценка, замечания, варианты
│   ├── voice.js               # голосовой ввод (MediaRecorder → /api/transcribe)
│   ├── accents.js             # акценты партий: jade / mint / teal / lime
│   ├── core/                  # validator, code-model, storage, share, recorder, wav,
│   │                          # highlight, visual-plan
│   ├── presets/               # шесть встроенных пресетов
│   └── styles/                # tokens / layout / components / animations
├── server/                    # Node-прокси: /api/generate (SSE), /api/fix,
│                              # /api/transcribe, /api/music/*, промпты, health
│   ├── llm/                   # router.js — мультипровайдерный роутер LLM
│   └── music/                 # mini.js, notes.js, extract.js, features.js,
│                              # references.js, score.js — разбор и оценка
├── deploy/                    # nginx-music.conf, ecosystem.config.cjs, deploy.sh
├── scripts/                   # check-secrets, check-presets, probe-music, calibrate
└── tests/                     # vitest: юнит-тесты + фикстуры битого кода
```

## Деплой

```bash
bash deploy/deploy.sh   # сборка, rsync в /opt/strudel, pm2 restart strudel, новый nginx-блок
```

Конфиг nginx ставится отдельным файлом `music.conf` — существующий конфиг основного сайта не меняется.

## Проверки

```bash
npm test              # 106 юнит-тестов (vitest)
npm run check:presets # мини-нотация пресетов настоящим парсером Strudel
npm run check:secrets # ключи не попали в репозиторий
npm run build         # продакшн-сборка в dist/
node scripts/probe-music.mjs   # разбор всех пресетов с оценками по критериям
node scripts/calibrate.mjs     # подбор весов критериев под оценки человека
```

`npm run check:presets` важен: Strudel принимает в mini-нотации паузу `~`, а не `.`. Пресеты и сгенерированный код проверяются настоящим парсером, а линтер в `src/core/validator.js` ловит точку на месте паузы до запуска.

> Примечание: барабанные сэмплы (dirt-samples) загружаются лениво при первом исполнении кода с GitHub-CDN Strudel; синтезаторы работают без них. Для генерации кода нужен интернет и валидный ключ.
