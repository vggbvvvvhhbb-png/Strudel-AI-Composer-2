# Strudel AI Composer

Веб-приложение: вы описываете музыку словами, AI-агент генерирует код на [Strudel](https://strudel.cc/) (live-coding музыкальный фреймворк), и код сразу исполняется в браузере с визуализацией партий.

Три страницы:

| Адрес | Что это | Для кого |
|---|---|---|
| `/` | обложка: одно поле, одна кнопка, примеры в один клик | тот, кто пришёл впервые |
| `/studio.html` | студия в три шага: опишите → слушайте → правьте | тот, кто работает с треком |
| `/tinder.html` | страница суждения: две музыки, одно суждение | рецензент, который учит модель вкусу |

- **Текст → код** — LLM генерирует Strudel-код со стримингом (эффект живой печати)
- **Структурная композиция** — модель выбирает идеи (гармония, форма, роли, энергия), компилятор собирает по ним код. Трек развивается во времени: секции, смена гармонии, переходы
- **Трейс и таймлайн** — видно, как строился трек: спека, оценка, шаги улучшения; над редактором — блоки секций и кривая энергии
- **Музыкальный разбор** — код измеряется по объективным метрикам (темп, плотность, грув, лад, диапазон, регистры) и получает оценку 0–100 с прозрачным разбором по критериям
- **Звуковой разбор** — трек рендерится в браузере тем же DSP-ядром, что звучит: громкость (LUFS), true peak, полосы, тишина, повторяемость рендера. Аудио-блок — 20% оценки, замечания машиночитаемые («тише бас» → команда, а не текст)
- **Обратная связь** — «✨ Улучшить по разбору»: модель переписывает трек под конкретные замечания («темп 90 при цели 124–142», «мало атак», «бас и мелодия в одной октаве»)
- **Варианты A/B** — best-of-N: несколько вариантов под разными углами, каждый с оценкой, лучший — сверху
- **Живая партитура** — под каждой `$PART:` крупный пианоролл или осциллограф, с кодом партии над ним
- **Исполнение** — `@strudel/web`: звук сразу после генерации
- **Микшер** — громкость, mute и solo по каждой партии, живые индикаторы уровня
- **Правки по описанию** — «✨ Улучшить» показывает diff и применяет его после подтверждения
- **Голос** — необязательный ввод голосом (Groq Whisper); без ключа кнопка скрыта
- **Пресеты и история** — шесть встроенных пресетов, история генераций, экспорт/импорт, ссылка на трек
- **Дизайн** — тёмно-нефритовый (jade) по умолчанию, альтернативная тема obsidian, без UI-библиотек
- **Сэмплы** — `dirt-samples` (bd, sd, hh, cp, 808*, breaks* …) и `shabda:piano`; подгружаются сами, имена — без `.bank(...)`

## Установка

```bash
npm install
cp .env.example .env   # вставьте свои ключи
npm run dev
```

Откроется `http://localhost:5173`. При первом клике разблокируется звук (политика браузеров для AudioContext).

## API-ключи

| Переменная | Где получить | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | https://platform.openai.com/api-keys | генерация Strudel-кода |
| `OPENAI_MODEL` | — | модель генерации |
| `OPENAI_BASE_URL` *(необязательно)* | совместимый прокси | если регион блокирует api.openai.com |
| `OPENAI_FALLBACK_MODEL` *(необязательно)* | — | резервная модель, если основная недоступна |
| `GROQ_API_KEY` *(необязательно)* | https://console.groq.com/keys | транскрипция голоса; без него кнопка микрофона скрыта |
| `OLLAMA_MODEL` *(необязательно)* | — | локальный инференс без интернета и оплаты |
| `ANTHROPIC_API_KEY` *(необязательно)* | https://console.anthropic.com | ещё один провайдер в роутере |

Провайдеры перебираются по порядку `LLM_PROVIDERS` (по умолчанию `openai`):
если текущий недоступен, запрос уходит следующему. Доступны `openai`, `groq`,
`ollama`, `anthropic` — OpenAI-совместимые и Anthropic Messages API.

Ключи используются только на стороне сервера: запросы идут через прокси Vite (`/api/generate` → LLM), на фронтенд не попадают.

## Как пользоваться

1. Откройте `/` и опишите трек в поле «Опишите трек» — можно выбрать готовый
   пример. Кнопка «✨ Создать трек» ведёт в студию с подставленным описанием и
   запускает генерацию.
2. В студии пройдите три шага: **Опишите** → **Слушайте** → **Правьте**.
   - Шаг «Слушайте»: визуализация партий, оценка трека и замечания по измерениям.
   - Шаг «Правьте» (кнопка «Показать код»): редактор кода, микшер, правки по фразе.
3. «🎼 Разобрать трек» — оценка по объективным метрикам: что мешает и почему.
4. «🛠 Исправить по замечаниям» — модель перепишет трек под замечания; показывается «было → стало».
5. «🎲 Сравнить два варианта» — три варианта под разными углами, каждый с оценкой; лучший сверху.
6. «🎤» рядом с описанием — записать голосовое описание (нужен `GROQ_API_KEY`); автоотправки нет.

Альтернативные пути (структурная композиция, свободный код, варианты плана) спрятаны
в блок «Другие способы» — для обычного сценария они не нужны.

### Два режима генерации

| Режим | Что делает модель | Что даёт |
|---|---|---|
| **Структурный** (по умолчанию) | планирует секции, гармонию, энергию и паттерны ролей в TrackSpec | после проверки спеки компилятор детерминированно создаёт Strudel-код |
| **Свободный** | пишет код целиком | максимум свободы, но без гарантии формы |

Переключатель — под полем «Команда». Структурный путь: план →
`validateTrackSpec` → синхронная `compileTrackSpec(spec)` → оценка и повторное
улучшение с новой валидацией и компиляцией. Компилятор возвращает строку кода.
Единая схема — `src/schemas/track-spec.schema.js`: `meta`,
`structure.sections`, `parts.roles`. Старые верхнеуровневые `harmony/form`
не поддерживаются. Свободный режим проверяет готовый код; оба режима
сохраняют разбор и улучшение.

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Space` | play / stop |
| `Ctrl` + `Enter` | сгенерировать трек |
| `Ctrl` + `S` | сохранить пресет |

### Примеры команд

- «драм-партия в стиле Queen с мощным басом»
- «спокойная мелодия на пианино в тональности ля минор, 80 BPM»
- «добавь к текущему коду хай-хэты на каждую восьмую»
- «сделай бас тяжелее и замедли темп»

### Музыкальный интеллект (RAG-ассистент)

Панель «Музыкальный интеллект» в студии — ассистент с музыкальным
образованием (D-134…D-152):

- **База знаний**: локальный корпус из 148 проверенных паттернов Strudel с теоретическим
  обоснованием («почему это звучит»), гибридный поиск по метаданным
  (тональность, лад, роль, сложность) и эмбеддингам. Хранилище —
  Supabase + pgvector владельца или локальный датасет без сети;
  эмбеддинги — локальная Ollama `nomic-embed-text` (768, Apache-2.0).
  Нет Ollama — поиск честно деградирует до лексического и говорит об этом.
  Добавлены 113 авторских учебных записей по 15 направлениям и 12 жанровых
  гайдов. Удалённая база не обновляется автоматически: в замере 18.11.2026
  Supabase оставалась на 35 записях, загрузка требует отдельного запуска.
- **Жанровый композитор**: структурная композиция подшивает локальный гайд,
  проверяет только BPM и обязательные роли; до 3 попыток коррекции.
  Ритм, форма и аккордовый словарь пока остаются текстовыми рекомендациями.
- **Валидатор и петля**: сгенерированный код проверяется настоящим
  Strudel (синтаксис, события, ноты вне лада с номером такта,
  выдуманные пресеты/сэмплы); до 3 попыток исправления по структурному
  фидбеку, финал — честный отказ, а не мусор.
- **Объяснение кода**: детерминированное распознавание прогрессий
  (ii–V–I и др.), функций T/S/D, каденций; советы замен (тритоновая
  замена и т.п.) — без LLM, факты проверяемы.
- **Локальный референс (экспериментально)**: инструмент `analyze_reference`
  принимает ID готовой локальной аудиозадачи, получает Demucs-паспорт и
  направляет композитор измеренными признаками. До240с, DSP-окно≤12с;
  approved-тембры, не копирование исходного звука. Механика проверена,
  но живой гейт не закрыт: Demucs завершился3221225477 на12с WAV.
- Код применяется только по кнопке; счётчики вкуса и DPO-экспорт
  не трогаются.

Команды: `npm run rag:migrate` (миграция pgvector), `npm run rag:upload`
(идемпотентная загрузка датасета), `npm run rag:probe` (зонд поиска),
`npm run rag:eval` (оценка качества на 20 запросах),
`node scripts/probe-rag-ui.mjs` (браузерный зонд панели).
Ключи Supabase — только в `.env` (образец — `.env.example`).

## Деплой

Два пути — под реальный сервер (docker + Caddy) и «классический» (pm2 + nginx).

```bash
bash deploy/deploy-server.sh   # боевой сервер: tar по ssh → /opt/strudel,
                               # сборка образа, сервис strudel в общей docker-сети,
                               # отдельный сайт-блок в Caddy
bash deploy/deploy.sh          # pm2 + nginx (шаблон: домен и путь задаются переменными)
```

`deploy/deploy-server.sh` не трогает существующие сервисы: поднимается только
свой, а в Caddy добавляется отдельный сайт-блок (Caddyfile сохраняется в
`.bak`, при неудачной проверке конфига — откат).

## Проверки

```bash
npm test              # юнит- и интеграционные тесты (vitest); актуальное число — в отчёте запуска
npm run check:presets # мини-нотация пресетов настоящим парсером Strudel
npm run check:secrets # ключи не попали в репозиторий
npm run check:taste   # гейт выученной цели: реестр метрик, признаки, модель, CV
npm run taste:train   # обучить выученную цель на человеческих парах → docs/TASTE.md
npm run check:prompts # пул промтов очереди совпадает с корпусом Baseline-0 (по хэшу)
npm run build         # продакшн-сборка в dist/
node scripts/probe-music.mjs   # разбор всех пресетов с оценками по критериям
node scripts/calibrate.mjs     # подбор весов критериев под оценки человека
```

`npm run check:taste` важен по той же причине, что и остальные проверки: он
доказывает, что модель **не** допущена в скор, пока нет human-пар. Символьный
скор — гипотеза, и оптимизировать гипотезу, не проверенную людьми, нельзя.

`npm run check:prompts` следит за пулом промтов очереди: приёмка требует ≥50
**разных** промтов (§7.2), поэтому очередь не может питаться десятью
строками. Пул собран из корпуса Baseline-0 (60 стратифицированных промтов) и
сверяется с корпусом по хэшу.

`npm run check:presets` важен: Strudel принимает в mini-нотации паузу `~`, а не `.`. Пресеты и сгенерированный код проверяются настоящим парсером, а линтер в `src/core/validator.js` ловит точку на месте паузы до запуска.

> Примечание: барабанные сэмплы (dirt-samples) загружаются лениво при первом исполнении кода с GitHub-CDN Strudel; синтезаторы работают без них. Для генерации кода нужен интернет и валидный ключ.
