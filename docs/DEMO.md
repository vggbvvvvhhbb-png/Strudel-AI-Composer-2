# DEMO — сценарии демонстрации Strudel AI Composer

*Обновлено 18.11.2026 (сессия «Музыкальный интеллект»). Каждый сценарий
проверяем командой или зондом; «нет данных» говорится словами.*

## 1. Обложка: звук без регистрации

Открыть `/` → кнопка «Создать трек» → предрассчитанное демо звучит
≤5 с (4.0 с, −18.16 LUFS). Проверено гейтом A0 и тестом бандла.

## 2. Студия: трек из промпта за три шага

`/studio.html` → описание → план → код. Агент слева сам выбирает
инструменты (поиск, спека, компиляция), каждый шаг виден. Локальный
счёт кнопкой «Считать локально» через демон на машине владельца.
Демо-опера на пустом экране: 66 дорожек, 102 дорожки — 55.8 FPS.

## 3. Тембры: «пианино теплее, мелодия сохранена» (D-131/D-132)

Чип звука на партии таймлайна → панель пресетов (лицензия CC0,
паспорт, превью) → профиль warm ставит `tp-upright-soft-v1` первым →
применение меняет только `.s()` партии, события queryArc сохранены
(инвариант проверен тестом и зондом). В тиндере режим «тембры»:
одна партия, два инструмента, ответ «ни один»; метки не двигают
человеческий гейт композиции. Зонд: `node scripts/probe-timbre-ui.mjs`
(13/13 при человеческом темпе; E-020 — быстрые рендеры подряд
в трековом режиме ненадёжны, дефект superdough 1.3.0).

## 4. Музыкальный интеллект: ассистент с образованием (D-134…D-141)

Панель «Музыкальный интеллект» в студии:
1. Запрос «тёплые джазовые аккорды для lofi в ля миноре, 78 BPM» →
   «Сгенерировать с теорией»: видны шаги поиска по базе знаний
   (35 проверенных паттернов, Supabase + pgvector) и попытки
   валидации; обоснование («почему это звучит») отдельно от кода;
   код применяется только по кнопке.
2. «Объяснить код» на `chord("<Dm7 G7 CM7>")` в c:major →
   детерминированно: ii–V–I, функции S→D→T, аутентическая каденция,
   совет тритоновой замены G7→Db7. Без LLM — факты проверяемы.
3. Валидатор ловит выдуманные пресеты/сэмплы и ноты вне лада
   (с номером такта); петля self-correction до 3 попыток, финал —
   честный отказ, не мусор.

Зонд: `npm run build && node scripts/probe-rag-ui.mjs` (9/9,
скриншоты `docs/evidence/rag/`). Поиск: `npm run rag:probe`
(5 запросов, верная запись первая 5/5 в Supabase). Оценка качества:
`npm run rag:eval` (20 запросов × plain/RAG/RAG+петля, живая модель,
сводка `docs/evidence/rag/eval.json`, E-021).

## 5. Охотник за звуком: «найди редкий звук → бит» (D-119/D-120)

Агент: `freesound_search` (только CC0/CC-BY) → `sample_passport` →
`compose_spec(sampleId)` → компиляция → рендер; измеренный тон задаёт
тональность, темп атак — BPM, сэмпл слышен в рендере. Живой гейт E
12/12 за 87–115 с, цена цепочки ~$0.0002 видна в учёте.

## 6. Разбор трека (Deep Dive)

Загрузка своего аудио → паспорт трека по слоям, покрытие публикуется
вместе с баллом («нет данных» ≠ 0). `/razbor/<id>` — только с токеном.
Сепарация требует Python-окружения владельца (local/README.md) —
без него режим честно говорит `analysis.available = false`.

## Чего в демо НЕТ (честно)

- Слепого A/B «до/после» на людях (≥30 пар) — нужен владелец.
- Выученной цели вкуса в скоре — гейт людей не закрыт (10/60 пар, 5/50 промптов).
- Публикации: ворота `--release` красные по лицензиям двух банков
  (D-099/D-127, решение владельца открыто).
- Бит-в-бит рендера локально и на сервере (1 LSB, D-104/E-019;
  fingerprint совпадает точно).
