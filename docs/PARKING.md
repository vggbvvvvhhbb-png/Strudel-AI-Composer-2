# PARKING — что осознанно не строим сейчас

Парковка — это список идей, которые **выведены из объёма работ осознанно**, а не
забыты. Каждая строка отвечает на два вопроса: почему идея не входит в текущий
объём и что должно произойти, чтобы её открыть.

Правила парковки:

1. Идея попадает сюда только с причиной и с условием открытия. «Некогда» —
   не причина.
2. Идея, которая помешала бы измеримости или лицензионной чистоте, не паркуется,
   а запрещается (раздел 4).
3. Парковка не отменяет решения владельца: если владелец говорит «да» и
   называет цену — идея выходит из парковки и становится задачей с этапом.

Источники: промт миссии «Producer's Deep Dive × Strudel AI Composer» (§4, §6-S6,
§11, §12), `docs/AUDIT.md` (14.11.2026), `docs/LICENSES.md`, `docs/DECISIONS.md`
(D-072…D-088), `docs/DEEPDIVE_API.md`.

## 1. Что не строим сейчас

| Идея | Почему в парковке | Что нужно, чтобы открыть |
|---|---|---|
| **Соцсеть, граф знаний, чат-боты** | Прямой запрет промта миссии (§11.9). Продукт заявлен как «загрузил трек — получил код, который можно править», а не как платформа вокруг студии. Соцсеть и чат-бот — это отдельный продукт с отдельной аудиторией, модерацией и поддержкой; в пет-проекте их нечем кормить. Граф знаний решает задачу, которой у нас нет: знания о музыке уже лежат в `server/music/knowledge/` и в формате, пригодном для показа | Решение владельца, что продукт становится платформой; отдельный этап с бюджетом, безопасностью и модерацией |
| **Kubernetes, микросервисы** | Масштаб не тот: один сервер, 2 vCPU, 3.8 ГБ RAM (`docs/AUDIT.md` §6). Весь пайплайн режима «Разбор» — это три процесса: Node-сервер, Python-воркер анализа, контейнер рендера в headless-Chromium. K8s на таком железе — инфраструктура ради инфраструктуры: она съедает RAM, которая нужна Chromium и сегментации Demucs, и не даёт ничего измеримого | Измерение нагрузки, при которой один инстанс перестаёт справляться (очередь разборов, параллельные задачи), + отдельный бюджет на инфраструктуру |
| **Spleeter как замена Demucs** | Код — MIT, но веса ≈ MIT **не подтверждены**: README говорит только о коде, вопросы мейнтейнеру без ответа (`docs/LICENSES.md` §2). Это та же цепочка «лицензия кода ≠ лицензия весов», из-за которой взят Demucs. Замена нужна была бы ради лицензии, а Spleeter её не даёт | Решение владельца по весам Spleeter (`docs/LICENSES.md` §5, п. 6) или письменное разрешение от мейнтейнеров |
| **Экспорт `.als` / `.flp`** | Проприетарные форматы DAW: своя структура проекта, версии, пути плагинов. MIDI-экспорт уже покрывает перенос ритма и нот и в Ableton, и в FL Studio перетаскиванием (D-085), то есть заявленная пользовательская ценность закрыта | Подтверждённая совместимость формата (проект открывается в чужой DAW) и оценка трудозатрат против MIDI. Без этого — работа на версию чужого формата |
| **Ableton Link** | Link синхронизирует темп, а не ноты. Обещанный «Send to Ableton» перенёс бы только темп — код-двойник и так приезжает кодом и MIDI. Плюс Link тянет за собой постоянно открытый сетевой сервис на сервере без GPU и с лимитом RAM | Реальная потребность в синхронизации темпа между устройствами в сценарии пользователя + проверка, что Link не конфликтует с экспортом MIDI |
| **Тексты песен (лирика)** | Не генерируем по существу, а не по времени: лирика не выводится из измерений аудио, а значит, была бы выдумкой. Это прямо ломает принципы P1 («измеряем, не угадываем») и P8 («запрещено выдумывать») | Отдельная измеримая фича — например, распознавание вокальных фраз с оценкой уверенности. Сейчас в пайплайне таких измерений нет, и вокал по договорённости не воспроизводится (D-087) |
| **VR/AR** | Нет измеримой ценности для задачи «получить редактируемый код трека». Разработка интерфейса в VR стоит больше, чем весь режим «Разбор», и не проверяется нашим ядром измерений | Запрос от аудитории + решение владельца о смене продукта |
| **Essentia, madmom, ADTOF, MUSDB18, Open-Unmix** | Лицензии, а не качество: Essentia — AGPL-3.0 (на сетевом сервере это обязывает публиковать исходники сервиса) + модели CC BY-NC-SA; madmom — код BSD, но все модели CC BY-NC-SA; ADTOF — CC BY-NC-SA целиком; MUSDB18 — только исследовательские цели; Open-Unmix — код MIT, но веса по MUSDB. Правило стека по умолчанию: только MIT/BSD/ISC/Apache (D-083) | Письменные решения владельца по `docs/LICENSES.md` §5; для MUSDB18 допустимо только использование как бенчмарк-эталон разделения, не как публикуемый контент. Для Essentia — отдельно купленная коммерческая лицензия |
| **Spotify Web API (audio-features / audio-analysis)** | Технически закрыто: с **27.11.2024** новые Web API-приложения не могут обращаться к Audio Features и Audio Analysis — работают только приложения, зарегистрированные ранее в extended mode. Отдельный запрет: Spotify-контент нельзя использовать для обучения ML-моделей. Метаданные треков при этом берём через oEmbed и публичные страницы | Не открывается для нового приложения. Данные о треке — только из загруженного файла |
| **Поиск похожих по CLAP-эмбеддингам (M6)** | Отложен по лицензионной гигиене, а не по сложности: нужен корпус **только CC0/CC-BY с проверкой каждого сэмпла**, а в родословной LAION-Audio-630K лицензии смешанные, включая NC (`docs/LICENSES.md` §5, п. 7). Плюс отдельные решения: pgvector, хранилище, индекс | Собранный и поштучно проверенный корпус CC0/CC-BY + решение владельца по весам CLAP + решение по БД и векторизации. Срок из промта — после 90 дней |
| **Лаборатория: спектрограмма, EQ/фильтры на стемах, reference mixing (M5)** | План ставит её явно после ядра: без работающего разбора и без стемов лаборатория даёт инструмент над пустотой. Сравнение «свой микс против оригинала» имеет смысл только тогда, когда есть честные стемы-эталоны | Вертикальный срез end-to-end (загрузка → разбор → двойник → сравнение) и стабильные стемы; для reference mixing — эталонные стемы, которых у коммерческих треков нет |
| **Библиотека: вход Google, заметки к таймкоду, приватные ссылки (M7)** | Это функция хранения и доверия, а не измерений. Вход через Google = аутентификация, восстановление доступа, политика данных; заметки к таймкоду — отдельная подсистема. Приватная ссылка упирается в то же, что описано в D-084: по ссылке отдаются только производные данные | Решение владельца по аккаунтам и аутентификации + готовый TTL и токен-механик для производных данных (D-084) |
| **GPU-хост для Demucs** | **ЗАКРЫТО решением владельца от 14.11.2026: GPU не берём** (D-089). Бюджета нет, время ожидания не критично, разделение работает как честный фоновый режим с оценкой по замерам (4-минутный трек — 14–27 мин). Замер S2 выполнен: 3.45–6.6 × realtime на 2 vCPU. Правило «p95 > 3 мин → GPU» **отменено** и не должно применяться обратно без нового запроса владельца | Не открывается. Пересмотр — только по прямому решению владельца (D-089) |
| **Скачивание аудио чужих треков** | **Не делаем никогда.** Запрет промта (§11.3) и лицензионная гигиена: файлы gold set загружает сам владелец через UI, публичные демо — только свои треки или проверенные CC | Не открывается. Допустимо только CC0/CC-BY с проверкой каждого сэмпла — это материал для демо и автотестов, а не выкачивание чужого контента |

## 2. Прорывные идеи после Gate (промт миссии §12)

Оценки — оценки, не измерения: impact / effort / risk, шкала 1-5, где 5 — максимум.

| Идея | Идея в одну строку | Impact | Effort | Risk |
|---|---|---|---|---|
| Стиль-трансфер грува | «сделай МОЙ бит в духе референса»: дескрипторы трека-референса (сетка, свинг, тембры, структура) применяются к паттерну пользователя | 5 | 4 | 3 |
| Детектор slowed/sped-up | если отношение BPM original/slowed совпадает с отношением длительностей — восстанавливать оригинальный темп и подавать как фичу | 4 | 3 | 3 |
| Поиск по текстовому запросу (SAM Audio) | «выдели каубелл» по описанию, а не по имени стема | 4 | 5 | 4 |
| Продюсерский нарратив (L2) | 2-3 предложения «почему это качает» строго по измерениям + «как проверить на слух» | 4 | 2 | 2 |
| Живой джем поверх разбора | двойник играет, пользователь импровизирует сверху, запись в «● Rec» → «трек-ответ» | 4 | 3 | 3 |
| Эволюционный саунд-дизайн | численный поиск параметров синтеза по метрикам вместо одной LLM-итерации | 3 | 5 | 4 |
| «ДНК-паспорт» трека | сравнение двух треков по дескрипторам: что у них общего и почему они качают одинаково | 3 | 3 | 2 |
| Тренажёр продюсера | «повтори этот хэт-паттерн на слух», система скорит похожесть онсетов и velocity | 3 | 4 | 2 |
| Слепая арена | A/B «оригинал против двойника» с голосованием и рейтингом версий транспайлера | 3 | 4 | 3 |
| Стем-пак экспорт | MIDI + JSON + код + рецепты одним архивом для DAW | 2 | 2 | 1 |

Условие входа для всех: закрыт вертикальный срез режима «Разбор» end-to-end и
записан baseline-метрик (D-086). До этого любая из этих идей конкурирует за
время с ядром, а не расширяет его.

Это не парковка, а решения, которые ждут владельца. Пока их нет, соответствующие
компоненты не идут в стек (`docs/LICENSES.md` §5).

| Basic Pitch: принимаем ли риск NC-происхождения (MAESTRO, iKala) или пишем свою модель | Пики-трек баса в двойнике | `docs/LICENSES.md` §5 (п. 3); D-081 |
| Лицензия банка `tidalcycles/dirt-samples` и папки `breaks125` | Публичный релиз студии с чужими сэмплами | `docs/LICENSES.md` §5 (п. 4) |

| GPU-хост для Demucs | ЗАКРЫТО: решение владельца — CPU-only, D-089 | D-089; раздел 1 |

## 4. Что не паркуется, а запрещено

Эти ограничения не снимаются решением открыть парковку — они требуют явного
пересмотра самих правил продукта.

1. **Обещать клон трека.** Продукт — «узнаваемый скелет трека в коде». Вокал,
   точное сведение и мастеринг не воспроизводятся, и это пишется в каждом
   отчёте (`honesty.caveats`). D-087.
2. **Добавлять числа, которых нет в измерениях.** LLM получает только JSON
   измерений и метрик. D-086.
3. **Считать метрику «нет данных» нулём.** Отсутствующий слой исключается из
   оценки, а не штрафует двойник. D-080.
4. **Выкачивать и публиковать чужое аудио и чужие стемы.** D-084 и раздел 1.
5. **Ломать существующую студию.** Режим «Разбор» включается feature flag'ом и
   отдельной вкладкой; регресс (`npm test`, `lint`, `check:*`, `build` +
   `bundle:budget`) зелёный до каждого коммита. `docs/ARCHITECTURE_MAP.md` §4.
