# Метрики v2: как измеряется развитие трека

Документ описывает метрики второго поколения: что именно измеряется, по
каким формулам, какие целевые диапазоны и как устроен скор.

## Зачем второй слой

Скор v1 (`server/music/score.js`) оценивает **один цикл**: темп, плотность,
грув, тональность, диапазон, разделение регистров, аранжировку, движение
мелодии, воздух, разнообразие партий. Он отвечает на вопрос «правильно ли
этот кусок звучит».

Но трек — это не кусок, а последовательность. Трек из 64 тактов, в котором
4 такта повторены 16 раз, проходит все десять критериев v1 идеально: ровный
ритм, всё в ладу, ноты не выходят за диапазон. При этом в нём нет ничего
развивающегося.

Метрики v2 отвечают на другой вопрос: **что меняется по ходу трека**.

## Источник данных

Только события настоящего Strudel (`server/music/strudel-runtime.mjs`,
`runStrudel`). Никакого FFT, никакого звука, никакого собственного парсера
mini-нотации.

Причина зафиксирована в `docs/DECISIONS.md` (D-001): свой парсер разбирает
один-два такта и не понимает `arrange`, `stack`, `<…>/n`, `.slow`, `.mask`,
`.struct`. Расхождение измерено: на `<0 5 2 6>/2` свой парсер даёт **1**
событие, Strudel — **4**. На структурированном треке, собранном компилятором,
свой парсер не находит **ни одного** события.

### Что лежит в событии

```js
hap.value = { note: "F3", s: "sawtooth", cutoff: 600, room: 0.5, gain: 0.7 }
```

Значения параметров эффектов лежат в самом событии — это позволяет считать
автоматизацию по факту, а не по тексту кода.

## Кадры и окна

- **Кадр** — один такт. Считаются: число активных партий `A`, плотность
  онсетов `D`, 12-мерная гистограмма классов высот `H`, центроид регистра,
  множество корней.
- **Окно** — 4 такта (`WINDOW_BARS`). Окна используются для новизны и
  вариативности: соседние окна — это «куски трека», которые сравниваются.

Длина трека берётся из блоков `arrange` (`arrangeLength`): сам `arrange`
зацикливает материал, поэтому по событиям длину не определить. Трек без
`arrange` считается длиной по горизонту опроса.

## Метрики

### 1. Кривая энергии

```
E_b = 0.5 · (A_b / A_max) + 0.5 · (D_b / D_max)
```

- **Динамический диапазон** = P90 − P10 по значениям `E`.
- **Сходство с кривой формы** = 1 − нормированный L1 с эталонной кривой
  (энергия волной: низ в начале, пик в середине, спад в конце).

Целевые диапазоны размаха (`ENERGY_RANGE_TARGETS`):

| Стиль | Размах | Стиль | Размах |
|---|---|---|---|
| techno | 0.25–0.60 | lofi | 0.08–0.30 |
| house | 0.25–0.60 | ambient | 0.05–0.25 |
| dnb | 0.25–0.65 | jazz | 0.10–0.35 |
| trap | 0.20–0.55 | rock | 0.20–0.55 |
| synthwave | 0.20–0.55 | cinematic | 0.15–0.50 |

Электронные жанры — широкие (интро и дроп различаются сильно), lo-fi и
эмбиент — узкие (трек ровный по замыслу).

### 2. Гармонический ритм

Аккорд в такте — множество классов высот гармонических партий (bass, sub,
pad, chords, arp, lead, texture).

- **Смены аккорда** — такты, где множество изменилось.
- **Изменений на 4 такта** = смены / длина × 4.
- **Различных аккордов** — число уникальных множеств.
- **Расстояние между соседними аккордами** — Жаккар по множествам классов.
- **Флаг «обои»** — одна гармония держится больше 8 тактов подряд.
  Не ставится для pedal-стилей: `ambient`, `lofi`, `cinematic` (`PEDAL_STYLES`).

### 3. Новизна секций

Расстояние между соседними окнами по вектору `[H, D, A, регистр]`:

```
d = (L1(H) / 2 + min(1, |ΔD| / 16) + min(1, |ΔA| / 8) + min(1, |Δрегистр| / 48)) / 4
```

- **Развитие** — среднее расстояние выше `NOVELTY_LOW` (0.05).
- **Не хаос** — максимум ниже `NOVELTY_HIGH` (0.60).
- **Доля почти-повторов** — доля окон, похожих (на расстоянии < 0.08) на
  какое-либо более раннее. Нужна, чтобы отличать форму «куплет/припев» от
  бесконечного нового материала: у трека с формой повторы обязаны быть.

### 4. Вариативность по партиям

- **Доля уникальных окон** — сколько раз рисунок партии отличается от
  предыдущих. Считается по окнам в 4 такта, а не по тактам: в треке с
  секциями по 8–16 тактов рисунок внутри секции закономерно один, и доля
  уникальных *тактов* падает математически (6 из 64 = 0.09), делая цель
  недостижимой. По окнам тот же трек даёт 6–8 уникальных из 16.
- **Цели**: лид/арп ≥ 0.30, ударные ≥ 0.15 (`VARIATION_TARGETS`).
- **Фразовые n-граммы** — тройки окон подряд; их разнообразие показывает,
  есть ли в треке повторяющиеся фразы.
- **Флаг «бас идентичен»** — два куска трека с одинаковым рисунком баса
  (не менее 8 тактов подряд). В замечании указываются такты.

### 5. Разнообразие партий

- **Попарный Жаккар сеток онсетов** (сетка 1/16) между партиями. Чем выше,
  тем больше партии дублируют друг друга.
- **Число различных ролей** и **число регистров**.

### 6. Автоматизация

Доля параметров эффектов, значение которых **меняется** от события к
событию, от всех параметров.

Считается по значениям событий, а не по тексту кода:

```js
// так — автоматизация (значения меняются)
.gain(sine.slow(4).range(0.2, 0.9))
.gain("<0.3 0.9>")

// так — НЕ автоматизация (значение одно и то же)
.gain(0.5)
```

Обе формы проверены пробой (`tests/spike/metrics-probe.mjs`): у первых двух
уникальных значений 3 и 2, у последнего — 1.

## Скор v2

`server/music/score-v2.js`. Старые десять критериев сохраняются и
масштабируются до **60 %** веса; новые пять групп занимают **40 %**.

| Критерий | Вес | Что измеряет |
|---|---|---|
| *старые десять* | ~60 | темп, плотность, грув, лад, диапазон, регистры, аранжировка, движение, воздух, ритм |
| Прогрессия и форма | 12 | размах энергии, новизна без хаоса, доля повторов |
| Гармоническое движение | 10 | смены аккорда на 4 такта, без «обоев» |
| Разнообразие партий | 8 | число партий, ролей, регистров, Жаккар сеток |
| Вариативность | 5 | уникальность рисунков, отсутствие повторяющегося баса |
| Автоматизация | 5 | доля параметров, меняющихся во времени |

Итог: `total = oldTotal + newTotal`, максимум 100.

**Если трек короче 16 тактов** (`MIN_FORM_BARS`), новые критерии **не
применяются** — вместо них выдаётся замечание «нет формы»: на таком треке
их не измерить.

### Где считаются старые критерии

Старые критерии пересчитываются по событиям Strudel
(`server/music/metrics/events.js`), а не по собственному парсеру. Формат
результата совместим с `analyzeTrack`, поэтому `scoreTrack` не ломается.

Причина: на структурированном треке свой парсер не находит ни одного
события, и все десять критериев выдавали бы мусор («плотность 0 атак на
такт», «диапазон 0 полутонов»).

## Защита от читерства

Adversarial-фикстуры в `tests/fixtures/cheat/` — настоящий Strudel-код,
который исполняется:

| Фикстура | Что имитирует | Что должно быть наказано |
|---|---|---|
| `a-repeated-cycle.js` | 4 такта × 16 с одним sweep на фильтре | размах энергии 0, гармония не меняется, новизна 0 |
| `b-out-of-scale.js` | случайные ноты вне лада при богатой форме | низкий `scaleFit` (0.35) несмотря на разнообразие |
| `c-same-rhythm.js` | 8 партий с одним рисунком | Жаккар сеток = 1.0, разнообразие падает |
| `d-static-params.js` | эффекты, но все параметры — константы | доля автоматизации = 0 |

**Приёмка:** каждая фикстура обязана получить балл **ниже** эталонного
трека (скомпилированный трек из нормальной спеки). Это проверяется тестом
`tests/unit/metrics-v2.test.js`; если метрику сломать, тест падает.

Текущие значения (проверено пробой `tests/spike/metrics-v2.probe.mjs`):

| Трек | Балл | Δ к эталону |
|---|---|---|
| Эталон (скомпилированный трек) | 83.8 | — |
| (a) один цикл × 16 | 57.7 | −26.1 |
| (b) ноты вне лада | 74.7 | −9.1 |
| (c) 8 партий одним ритмом | 55.9 | −27.9 |
| (d) статичные параметры | 66.4 | −17.4 |

### Как «обмануть» скор было НЕЛЬЗЯ

- **`.scale(key)` гарантирует попадание в лад.** Степень, переведённая
  масштабом, всегда в ладе по построению. Чтобы получить ноты вне лада,
  нужны буквенные имена (`note("c#4 e4")`). Это открытие пробой: первая
  версия фикстуры (b) использовала `n(...).scale(key)` и была «в ладе»,
  несмотря на задумку.
- **Число партий сверх профиля — не дефект аранжировки.** Эталон имеет
  ровно 6 партий (профиль technо требует 4–6), иначе сравнение штрафовало
  бы эталон за не относящийся к делу признак.
- **Транспозиция партий.** Бас, пэд и арпеджио собираются из степеней лада
  и без транспозиции звучат в одной октаве. Компилятор опускает бас на две
  октавы (`-24`) и поднимает арпеджио и лид на октаву (`+12`) — проверено
  пробой (`tests/spike/transpose-probe.mjs`): `.transpose()` работает только
  ПОСЛЕ `.scale(key)`.

## Ограничения

1. **Метрики v2 требуют исполнения Strudel** — это медленнее разбора
   текста, но для трека в 64 такта занимает десятки миллисекунд.
2. **Скор — не истина.** Это прозрачная обратная связь для модели, а не
   оценка красоты. Веса подбираются калибровкой по оценкам человека.
3. **Доля уникальных окон** не ловит вариативность *внутри* секции: если
   партия меняет рисунок на каждом такте, но окна совпадают, метрика этого
   не увидит.
4. **Расстояние окон** — эвристика, а не метрика в строгом смысле: она
   симметрична, но не транзитивна.
5. **Педальные стили** не штрафуются за долгую гармонию — но и не
   награждаются за её смену: порог «обои» для них просто не применяется.
