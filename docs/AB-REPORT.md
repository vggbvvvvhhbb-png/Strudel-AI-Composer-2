## Как мерить

1. Открыть `/tinder.html` на студии (или локально: `npm run dev` → `/tinder.html`).
2. Нажать «Начать», разрешить звук.
3. Слушать оба варианта целиком. Клавиши: `←` лучше A, `→` лучше B, `↓` ничья,
   `Space` — переслушать.
4. Каждая десятая пара — повтор тех же треков с переставленными сторонами: из
   этих сравнений считается надёжность рецензента.

Метки пишутся в `server/data/preferences.jsonl` (вне git, без PII).
Статистика — `GET /api/preference/stats`, выгрузка chosen/rejected —
`GET /api/preference/export`, удаление — `DELETE /api/preference`.

## Что уже сделано, чтобы сравнение было честным

| риск | как закрыт |
|---|---|
| «громче = лучше» | громкость выровнена **только гейном**, к тихому из двух; лимитер не трогаем |
| порядок выдаёт систему | стороны переставлены детерминированно по индексу пары |
| рецензент невнимателен | каждая десятая пара — повтор с переставленными сторонами |
| метки скрыты, но понятно, что сравнивать | показан промпт, не имена кандидатов |
| «пара» из двух одинаковых треков | кандидаты перебираются, пока коды не разойдутся |

## Пороги приёмки (бриф §7.2)

| цель | пар | критерий |
|---|---|---|
| разведка | 20 | ≥15 побед (двусторонний p ≈ 0.04) |
| go/no-go по фиче | 40 | ≥26 побед = 65 % (односторонний p ≈ 0.04) |
| приёмка проекта | ≥100, ≥50 промтов, ≥2 рецензента | ≥60 побед; нижняя граница Wilson 95 % > 50 % |
| надёжность рецензента | повторы | согласие ≥80 % |

24/40 (60 %) **не значимо** (p ≈ 0.13). Пары одного промта не независимы —
считаются кластерами по промту.
