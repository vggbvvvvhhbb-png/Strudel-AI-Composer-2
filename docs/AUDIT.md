# Аудит проекта «Strudel AI Composer» (2026-11-06, до фазы A)

Исходное состояние: один коммит `477ee1b`, 13 файлов, Vite + vanilla JS + `@strudel/web@1.3.0`.

## Что работает
- **Сборка** `vite build` — проходит, бандл ~644 kB (Strudel-движок, ожидаемо).
- **Движок** `src/strudel-engine.js`: одноразовая инициализация `initStrudel`, `evaluateCode`,
  `stop/reset` через `hush()`, разблокировка звука по клику (аудио-гейт в `index.html`).
- **UI** `src/ui.js` + `index.html`: поле команды, кнопки Исполнить/Стоп/Сброс, лог, рендер `pianoroll`.
- **Стили** `src/styles.css`: тёмно-синяя тема, моношрифт, адаптивная сетка.

## Что сломано / отсутствовало
- **Ключи на фронте**: `src/agent.js` ходил на OpenAI/Groq напрямую с ключом из запроса
  пользователя — ключи обязаны жить только на сервере.
- **Несуществующие эндпоинты**: `/api/chat` и `/api/transcribe` в `vite.config.js` вели в никуда;
  `src/voice.js` дублировал логику `agent.js` и был мёртвым кодом.
- **Нет стриминга**: ответ LLM приходил целиком, эффект «живой печати» отсутствовал.
- **Нет валидации кода**: битый код от LLM падал в консоль без диагностики и автофикса.
- **Нет микшера, транспорта (BPM/key), пресетов, истории, шеринга, записи WAV** — в рамках фаз B/C/D.
- **`.env` в репозитории отсутствовал**, `README` обещал `npm run dev` без серверной части.

## Что дублировалось
- HTTP-клиент LLM был продублирован в `agent.js` и `voice.js` → оба удалены,
  единый клиент вынесен в `server/llm/client.js` + `src/api/client.js`.

## Секреты
- `git log -p -S"sk-"` и `grep -rn "sk-\|gsk_\|API_KEY"` — реальных ключей в коде и истории НЕТ
  (только плейсхолдеры в `.env.example`). Присланный в чате ключ записывается владельцем в
  локальный `.env` (в `.gitignore`); в код не попадает.
- Добавлены `scripts/check-secrets.js` (regex `sk-`/`gsk_`) и pre-commit хук.

## Целевая архитектура (фазы A–D)
Node-прокси на 127.0.0.1:3001 (Express, helmet, rate-limit, zod) → SSE-генерация →
валидатор (статика + тихий прогон в REPL) → автофикс ≤2 → REPL `evaluate()` с пианороллами.
Голосовой модуль исключён по решению владельца (2026-11-06): «голосом пользоваться не буду».

## Аудит раздела 1.1 (дизайн-направление), 2026-11-07
Проверено в браузере на `http://127.0.0.1:3001` в обеих темах, десктоп и мобильный вид.

**Что уже было готово (~95%)**: палитра jade/obsidian в `src/styles/tokens.css`, стекло и глубина
панелей, подсветка синтаксиса, живая партитура с пианороллом под каждой `$PART:`, акценты партий
(jade/mint/teal/lime) в микшере, пульс play-кнопки в такт BPM, «дыхание» фона, `prefers-reduced-motion`,
адаптив с микшером в нижней шторке, горячие клавиши.

**Найдено и исправлено:**
1. **Палитра пианоролла была захардкожена в JS** (`src/pianoroll.js`) — тема obsidian не влияла на
   canvas. Теперь цвета читаются из CSS-переменных (`--note`, `--note-active`, `--roll-grid`,
   `--playhead`, `--scope-line`) и переключаются вместе с темой.
2. **Сырые цвета вне `tokens.css`** — ~40 литералов `rgba(...)` в `layout.css`/`components.css`/
   `animations.css`. Вынесены в токены (`--jade-rgb`, `--black-rgb`, `--danger-rgb`, …) как
   `rgb(var(--token) / alpha)`; тест `tests/unit/theme-tokens.test.js` запрещает новые литералы.
3. **Контраст красного текста был ниже WCAG AA** — `--danger` (#ff6b6b) давал 4.17:1 на панели.
   Добавлен `--danger-text` (#ff9b9b) для текста об ошибке; рамки/заливки остались на `--danger`.
4. **CSP резал AudioWorklet-модули Strudel** — они приходят как `data:text/javascript;base64`,
   а `script-src` разрешал только `blob:`. В консоли было «could not load AudioWorklet effects»,
   часть эффектов не поднималась. Добавлено `data:` в `script-src` (`server/index.js`).
5. **Барабаны и пианино в пресетах молчали** — код ссылался на банк `RolandTR909`, которого нет в
   манифесте `dirt-samples` (Strudel ищет ключ «RolandTR909_bd»), и на сэмпл `piano`, которого нет
   ни в одном наборе. Убраны `.bank(...)` из всех пресетов, добавлен набор `shabda:piano`,
   системный промпт переписан под реальные имена сэмплов. Guard — `tests/unit/samples.test.js`.
6. **Первый такт звучал без сэмплов** — манифест грузился параллельно с оценкой кода.
   Теперь `ensureSamples()` прогревается на старте, а `evaluateCode()` ждёт манифест (с лимитом 5 с).

**Проверено вручную:** манифесты `strudel.json` и `piano.json` отдают 200; аудиофайлы
`piano_0.wav`, `bd/BT0A0A7.wav`, `hh/000_hh3closedhh.wav`, `sd/rytm-00-hard.wav` реально загружаются;
в консоли нет ни ошибок, ни предупреждений; пианороллы анимируются, ноты светлые, активные — нефритовые.
