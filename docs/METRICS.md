# Реестр метрик

*Обновлено 14 ноября 2026 · спринт S4.0 · бриф v2 §4.5*

## Зачем реестр

Метрики и до этого считались. Реестр нужен, чтобы у каждой из них был
**id, единицы, диапазон, цель, источник и версия** — и чтобы отчёты
ссылались на id, а не на имя поля в объекте.

Три причины (в порядке важности):

1. **Веса скора были размазаны по трём модулям.** Символьные веса — в
   `src/oracle/score.js`, критерии аудио-блока — в
   `server/music/compose/audio-score.js`, формула смешивания v1/v2/аудио —
   там же. Ответ на вопрос «какой вес чем проверяется» требовал чтения
   трёх файлов. Теперь источник один, и у каждого веса стоит
   `validated: false` — честное «не проверено на людях» (бриф §2.8).
2. **Метрика без id ломается молча.** Переименование поля в отчёте
   рвало бы потребителя без единой ошибки. С id — падает тест.
3. **Обучение требует сопоставимых признаков.** Taste Model (§7.4)
   сравнивает треки попарно; значит, у признака должен быть зафиксированный
   состав, диапазон и источник.

## Где что лежит

| кусок | где |
|---|---|
| Объявления метрик и весов | `src/metrics/registry.js` |
| Отчёт → числа по id метрик | `src/metrics/extract.js` |
| Признаки для обучения | `src/taste/features.js` |
| Самопроверка полноты | `npm run check:taste` → `docs/evidence/taste/gate.json` |

## Уровни

* **L1 — символьные** (`source: 'symbolic'`): всё, что можно узнать о треке,
  не слушая его. Считает `src/oracle/metrics.js`, миллисекунды.
* **L0 — звук** (`source: 'render'`): только то, что видно в отчёте о
  рендере. Считает браузер (или рендер-воркер), сервер принимает числа
  только по форме (§2.5).

## Признаки для обучения

Из 43 метрик в обучение идут 42 (`src/taste/features.js` → `TASTE_FEATURE_IDS`):
37 символьных + 5 аудио. Причина расхождения: `audio.silenceInternal`
требует полного отчёта о рендере, который при построении пары ещё не
существует (звук меряется в браузере при прослушивании).

Признаки стандартизуются (среднее и отклонение по обучающей выборке).
Пропуск — это **null, а не 0**: «нечем измерить» и «ноль клиппинга» — разные
вещи, и смешивать их нельзя.

## Правило для новых метрик

1. Объявить в `src/metrics/registry.js`: id, label, unit, range, target,
   source, version.
2. Написать извлекатель в `src/metrics/extract.js` с тем же id.
3. Проверить: `npm run check:taste` требует 100 % покрытия реестра.
4. Если метрика нужна в обучении — добавить в `TASTE_FEATURE_IDS` и
   переобучить (`npm run taste:train`).

Метрика, у которой нет извлекателя, — это опечатка в объявлении, а не
«мера, которую посчитают потом».

## Что проверяет гейт

`npm run check:taste` → `docs/evidence/taste/gate.json`:

* id уникальны; все метрики извлекаемы;
* веса критериев символьного скора дают 100, аудио-критериев — 100,
  текстовых блоков — 1;
* признаки детерминированы; непомеренное = null; после стандартизации
  пропуск даёт 0, а не NaN;
* обучение детерминировано, вероятность обратима;
* leave-prompt-out работает на данных с известным ответом;
* интервал Уилсона считается верно;
* **модель не допускается**, пока живых пар меньше 60.
