# Фаза 3 — рендер и Audio QA

Задача фазы: получить **слушабельный, измеримый** результат. Рендер трека
измеряется тем же DSP-ядром, который звучит в реалтайме, и превращается в
машинночитаемые замечания — их и кнопка «Применить совет», и ассистент
потребляют как структуру, а не как текст.

## Поток данных

```
код (Strudel)
   └─► patternFromCode (без звука)      src/audio/engine/adapter.js
        └─► renderOffline → OfflineAudioContext → AudioBuffer
             └─► audioBufferToChannels → Float64Array[]
                  └─► buildMetricsReport → MetricsReport   src/audio/metrics-report.js
                       ├─► runAudioQa → замечания {code, params, suggestedCommands}
                       ├─► scoreAudioReport → 20% общего скора
                       └─► POST /api/music/compose {audioReport} → сервер
```

Ключевое: **метрики считает один и тот же код** в браузере (реалтайм и
офлайн), в Node-тестах и в CI. Расхождение между «что слышно» и «что в
отчёте» невозможно по построению.

## Коридоры приёмки

| Величина | Значение | Источник |
|---|---|---|
| Цель по громкости | −14 LUFS-I | §6 промта |
| Коридор приёмки | −16 … −12 LUFS-I | §6 промта |
| Потолок true peak | ≤ −1.0 dBTP | §6 промта |
| Пик отдельной партии | ≤ −3 dBFS | §6 промта |
| Клиппинг | 0 отсчётов на полной шкале | §6 промта |
| Headroom до мастера | ≥ 6 дБ | §6 промта |
| Сжатость (crest) | ≥ 6 дБ | §6 промта |
| Тишина в начале/конце | ≤ 0.5 с | §7 промта |
| Тишина внутри | ≤ 1 с | §7 промта |
| Повторяемость рендера | \|ΔLUFS\| ≤ 0.3 LU между двумя прогонами | §5 промта |
| Полосы (6) | коридоры измеряются в фазе 4 | §6 промта (H11) |

## MetricsReport — паспорт происхождения

Ни один потребитель не принимает числа без паспорта (§5 промта).

| Поле | Что значит |
|---|---|
| `engineVersion` | версии движка: `strudel-web@1.3.0/superdough@1.3.0` |
| `sampleRate` | частота рендера |
| `renderMode` | `offline` \| `realtime` \| `plan` |
| `repeatability` | `{runs, lufsDeltaDb, passed}` — два рендера и расхождение |
| `bars` | диапазон тактов рендера `[from, to]` |
| `lufsI`, `lufsM`, `lufsS` | громкость по ITU-R BS.1770 (K-взвешивание) |
| `truePeakDbtp` | true peak: оверсемплинг 4×, фильтр как в libebur128 |
| `peakDbfs` | пик по отсчётам (для справки, для приёмки не используется) |
| `clipCount` | сколько отсчётов достигли полной шкалы |
| `crestDb` | пик минус среднеквадратичный — сжатость |
| `bands` | 6 полос: sub, low, lowMid, mid, highMid, high (дБ) |
| `silence` | `{head, tail, internal}` — секунды тишины |
| `parts` | метрики партий отдельно: `{lufsI, peakDbfs, bands}` |
| `warnings` | текстовые предупреждения рендера |

Схема формы отчёта — `MetricsReportSchema` в `src/audio/metrics-report.js`.
Сервер проверяет **только форму**: аудио у него нет, числа приходят из
браузера и посчитаны тем же кодом, что звучит.

## Проверки Audio QA

| Код | Severity | Условие | Команда-подсказка |
|---|---|---|---|
| `repeatability-failed` | error | ΔLUFS двух рендеров > 0.3 LU | — (микс по метрикам отключён) |
| `repeatability-unknown` | warning | отчёт сделан по одному рендеру | — |
| `true-peak-over` | error | true peak выше −1 dBTP | `setMaster` (потолок −1.5), `setMix` (громкая партия) |
| `clipping` | error | clipCount > 0 | `setMix` −3 дБ по громкой партии |
| `lufs-above-corridor` | warning | LUFS-I > −12 | `setMix` по громкой партии |
| `lufs-below-corridor` | warning | LUFS-I < −16 | `setMix` по громкой партии |
| `silence-head` | warning | тишина в начале > 0.5 с | — |
| `silence-tail` | warning | тишина в конце > 0.5 с | — |
| `silence-internal` | warning | тишина внутри > 1 с | — |
| `part-too-loud` | warning | пик партии > −3 dBFS | `setMix` по этой партии |
| `part-silent` | warning | партия молчит в рендере | — |
| `crest-low` | warning | crest < 6 дБ | `setMaster` (компрессор 2:1, −22 дБ) |
| `band-skew` | warning | полоса вне коридора стиля (с фазы 4) | — |

Замечание — это структура: `{code, severity, label, hint, params,
suggestedCommands}`. Кнопка «Применить совет» и ассистент берут
`suggestedCommands` напрямую; текст `hint` нужен только человеку.

## Аудио-блок в скоре

| Блок | Вес | Когда участвует |
|---|---|---|
| v1 (разбор кода) | 60% | всегда |
| v2 (события Strudel) | 40% | всегда |
| аудио (рендер) | 20% | есть отчёт о рендере |

Вес аудио-блока — 20%, он переключаемый (`useAudio: false` в запросе). Если
отчёта нет, веса перераспределяются между v1 и v2 (60/40). Если отчёт есть:

```
итог = (v1·0.6 + v2·0.4)·0.8 + аудио·0.2
```

Критерии внутри аудио-блока:

| Критерий | Вес | Когда 0 |
|---|---|---|
| повторяемость рендера | 25 | ΔLUFS > 0.3 LU или повторяемость не измерена |
| громкость в коридоре | 25 | LUFS-I вне −16…−12 |
| клиппинг | 20 | clipCount > 0 |
| true peak в потолке | 20 | true peak > −1 dBTP |
| тишина | 10 | head/tail > 0.5 с или internal > 1 с |

Итог блока: 0…100.

## Повторяемость — правило приёмки

| Ситуация | Что делаем |
|---|---|
| два рендера, ΔLUFS ≤ 0.3 LU | `repeatability.passed = true` — метрикам можно верить |
| два рендера, ΔLUFS > 0.3 LU | `passed = false` → ошибка QA, autoMix по метрикам **выключен** |
| один рендер | `repeatability = null` → предупреждение, балл за повторяемость не засчитан |

Правило из §5 промта: autoMix и приёмка работают только при
`repeatability.passed`. «Неизвестно» ≠ «прошло».

## Как проверить

| Что | Команда |
|---|---|
| тесты метрик, QA, рендера, скора | `npm test` |
| браузерный спайк (реальные числа) | `npm run spike:offline` |
| сверка метрик с ffmpeg/libebur128 | `npm run validate:loudness` |
| сверка мастер-цепочки | `npm run validate:master` |

## Честные ограничения

| Ограничение | Почему | Когда |
|---|---|---|
| соло-рендеры партий не реализованы | нужна разметка партий в коде (id контроллера) | фаза 4 |
| сервер не проверяет числа отчёта | у сервера нет аудио; числа считает браузер тем же DSP-ядром | — |
| офлайн-рендер пересоздаёт контроллер superdough | офлайн-контекст отдельный (H3) | живой трек восстанавливается автоматически |
| коридоры полос по стилям отсутствуют | H11 — профилей жанров не существует | фаза 4, измеряется на корпусе |
