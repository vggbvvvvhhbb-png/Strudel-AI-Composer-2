# Composition IR — типизированный план композиции

*Версия 1 · 14 ноября 2026*

## Что это

Composition IR — план трека: настроение, форма, гармония римскими цифрами,
мотивы, грув, палитра, роли и их регистры. **Не код.** Код из плана собирает
детерминированный компилятор.

Смысл слоя (бриф v2 §5.2–§5.4):

| Проблема | Как решает IR |
|---|---|
| LLM пишет код — небезопасно и непрозрачно | LLM выдаёт JSON; он проходит Zod и становится данными, а не исполняемым текстом |
| «Сделай мрачнее» = перегенерация | Правка — чистая функция IR→IR с объявленным знаком изменения метрик |
| Соло-стемы дорого | `compile(IR, { roles })` — бесплатные соло-рендеры |
| Случайность «плывёт» при правках | Вся случайность — от counter-based PRNG по адресу (seed, секция, роль, шаг) |

## Слои

```
описание (текст)
  → planIR()            src/ir/intent.js    — эмоция, жанр, арка, гармония, мотив
  → CompositionIR       src/ir/schema.js    — Zod-схема, единственный контракт
  → compileIR()         src/ir/compiler.js  — чистая функция: IR → Strudel-код + спека
  → символьный оракул   src/oracle/         — метрики, замечания, скор без звука
```

Трансформации (`src/ir/transforms.js`) — единственный разрешённый способ
менять план. Каждая возвращает новый IR и не мутирует исходный.

## Что внутри IR

```js
{
  v: 1,
  seed: 42,                       // зерно детерминизма
  meta: {
    title, bpm, meter,
    key: { tonic: 'D', mode: 'minor' },
    mood: { valence, arousal, label, modifiers },
    genre, style,
  },
  palette: { chords: { ref: 'piano' }, ... },   // только известные звуки
  motifs: { hook: { degrees, steps, durations } },
  sections: [{
    id, kind, bars, energy, tension,
    harmony: [{ rn: 'i', color: '7', bars: 2 }],  // римские цифры
    layers: { kick: { plan, density, register, weight, lpf, gainDb } },
    enter: 'riser' | 'filter-open' | 'fill' | 'silence' | 'none',
  }],
  groove: { template, amount, swing, bassRhythm, offsetMs },
  mix: { sidechain: [{ src, dst, depth }], pan, orbit },
}
```

### Роли

`kick snare hats perc bass sub pad chords lead arp fx texture`

Роль описывается планом (`drums | bassline | chords | pad | melody | arp |
texture | fx`), плотностью (0…1), регистром (MIDI), весом в секции (0…1) и
частотой среза.

### Секции

Виды: `intro verse build peak break outro chorus drop air grow bloom fade`.
Каждая секция несёт целевую энергию (0…1) и напряжение (0…1) — по ним
считается целевая кривая, с которой сверяется измеренный профиль энергии.

## Гармония

Римские цифры → символы аккордов движка (`src/ir/harmony.js`). Поддержка
движка измерена пробами (`tests/spike/chord-symbols*.probe.mjs`):

| Символ | Работает | Символ | Работает |
|---|---|---|---|
| `C` `Dm` `Cm` `Caug` | да | `Cmaj7` | **нет** |
| `Csus` `Cadd9` `C7` | да | `Csus2` | **нет** |
| `Cm7` `Cm9` `C^7` `C^9` | да | `Cdim` | **нет** |
| `Dmadd9` `Dadd9` | да | `Fmsus` | **нет** (пустой аккорд!) |

Отсюда два правила: мажорная септима пишется `^7`, а минорный sus — без
префикса `m` (`Dsus`, а не `Fmsus`).

## Грув

Шаблоны (`src/ir/groove.js`): `straight swing laidback funk halftime drunken`.

Ключевое решение (D-050): свинг и микротайминг считает **компилятор**, а не
движок. `swingBy(x, n)` в @strudel/web 1.3.0 дублирует события (16 хэтов
превращаются в 24), а `swing(x)` без второго аргумента — no-op. Поэтому
шаблоны задают сдвиг в миллисекундах, а компилятор кладёт их в код через
`.late(ms(x))` по группам шагов.

Бюджет микротайминга: **|сдвиг| ≤ 20 мс** на любом темпе. Свинг 8-х на
80 BPM сам по себе даёт 45 мс — значит, он упирается в бюджет. Так и должно
быть: 20 мс на медленном темпе и есть правильный лоуфай-свинг.

## Правила компилятора

1. **Чистая функция.** Один IR → побайтно один код. Ни `Math.random`, ни
   `Date.now`, ни порядка обхода.
2. **Случайность адресная.** Хэш от `(seed, секция, роль, шаг)` — правка
   баса не пересыпает случайности барабанов.
3. **Роли по секциям.** Каждая роль в каждой секции — своя константа,
   собранная в `arrange([bars, ...])`.
4. **Регистр honored.** Октава баса берётся из `layer.register[0]`, мотив
   сдвигается на октаву оттуда же (иначе `shiftRegister` был бы пустой
   трансформацией).
5. **Только известные звуки.** Имя сэмпла проверяется по белому списку; в
   IR попасть может лишь `piano`, `triangle`, `bd`, `sd`, `hh`, `cp`, `oh`,
   синтезаторы движка.
6. **Мост в спеку v2** ограничивает темп 60…180 BPM — мост не имеет права
   выдать спеку, которую схема не примет.

## Трансформации

| Трансформация | Что делает |
|---|---|
| `darker` / `brighter` | лад по шкале яркости, регистр, фильтр, плотность |
| `energize` / `calm` | темп, плотность, энергия секций |
| `thin(role)` / `thicken(role)` | плотность и уровень одной роли |
| `shiftRegister(role, steps)` | регистр роли на октаву |
| `setMode(mode)` | лад тональности |
| `scaleTempo(factor)` | темп |
| `swapInstrument(role, ref)` | инструмент роли (только известные) |
| `addVariation(section)` | вариация мотива в секции |
| `extendSection(section, bars)` | длина секции |
| `swing(amount)` | доля свинга |
| `boostSection(section, delta)` | энергия секции и веса ролей в ней |
| `setHarmony(section, index, rn, color)` | ступень гармонии |
| `setBassRhythm(rhythm)` | ритм баса (слоты на 1/8) |
| `setGroove(template, options)` | шаблон грува, сила, свинг |

Локальность: правка роли X не меняет события других ролей. Монотонность:
чем больше величина, тем сильнее эффект в ожидаемую сторону. Обе
свойства проверяются тестами.

- `tests/unit/ir-*.test.js` — 167 тестов: схема, намерение, гармония, грув,
  компилятор (включая fuzz на 300 случайных IR и исполнение в движке),
  трансформации.
- `tests/unit/oracle-consistency.test.js` — быстрый оракул против движка.
- `npm run spike:ir` — сквозной прогон «текст → план → код → события».

## Что дальше

- **Планировщик (LLM).** Сейчас план строят правила (`planIR`). Схема уже
  готова к JSON-schema: LLM должен выдавать IR, а не код.
- **Намерения от UI.** Ручные правки в интерфейсе сохраняются как
  `overrides` и переживают перекомпиляцию.
- **Соло-стемы.** `compile(IR, { roles })` — механизм готов, не подключён.
