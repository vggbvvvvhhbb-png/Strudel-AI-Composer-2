# Фаза 0 — Spike: что Strudel реально умеет в этой версии

Все утверждения ниже проверены кодом, а не взяты из памяти или из внешних
статей. Проверяющий код — `tests/unit/spike-strudel.test.js`, черновые пробы —
`tests/spike/probe*.mjs`. Версия движка: `@strudel/web` 1.3.0, внутри
`@strudel/core` 1.2.6.

## Главный вывод

**Исполнение в Node без браузера работает.** Значит, метрики прогрессии можно
считать на настоящих событиях (`queryArc`), а не реконструировать из
регулярных выражений. Свой парсер mini-нотации остаётся для быстрых проверок,
но новые метрики v2 считаются по событиям Strudel.

## Как это сделано

Пакеты `@strudel/core`, `@strudel/mini`, `@strudel/tonal`, `@strudel/transpiler`
собираются как ESM-пакеты, но **прямой `import` в Node падает**:

```
SyntaxError: The requested module '@kabelsalat/web' does not provide
an export named 'SalatRepl'
```

`@strudel/core` импортирует `SalatRepl` из `@kabelsalat/web`, а у того пакета в
`main` лежит UMD-бандл без этого экспорта. Рабочий путь — загрузить готовый
UMD-бандл `@strudel/web` через `new Function` и достать экспорты из него. Тот
же приём уже применяется в `scripts/check-presets.mjs`.

Рабочий код: `server/music/strudel-runtime.mjs` → `runStrudel(code, {cycles})`
возвращает `{ok, error, parts, order}`, где `parts[NAME]` — массив событий с
`whole.begin` / `whole.end` в тактах.

### Две находки, без которых ничего не работает

1. **Нужен `setStringParser(mini)`.** В бандле строковый парсер по умолчанию не
   включён. Без него `n("0 5 2 6")` даёт **одно** событие со значением
   `"0 5 2 6"`, а не три ноты. В браузере это делает `initStrudel`; в Node мы
   вызываем явно. Это же касается `note()`, `s()`, `chord()`.

2. **Метки `$NAME:` — это не присваивание.** Синтаксис `$BASS: <expr>` —
   помеченный оператор (LabeledStatement), который в JavaScript ничего не
   присваивает. Настоящий Strudel прогоняет код через **транспилятор**, который
   превращает `$BASS: expr` в `expr.p('$BASS')`, а `Pattern.prototype.p`
   кладёт паттерн в реестр. Поэтому headless-исполнение идёт так:

   ```
   код → api.transpiler(code) → output → eval в песочнице → реестр по меткам
   ```

   Собственный `Pattern.prototype.p` в песочнице собирает партии в реестр.
   Метки видны микшеру: `parseParts()` даёт `["BASS", "DRUMS"]`, порядок
   сохраняется.

3. **Алиасы `._pianoroll()` / `._scope()` живут в приложении**
   (`src/pianoroll.js`), а не в Strudel. В Node нужны заглушки — иначе код с
   `._pianoroll()` не исполнится.

## Ответы на вопросы фазы 0

### 1. Публичный API Strudel

`scripts/extract-strudel-api.mjs` → `server/music/data/strudel-api.json`:
**1017 экспортов** и **1172 метода паттерна**. В списке есть `mini`, `n`,
`note`, `chord`, `s`, `stack`, `arrange`, `silence`, `cat`, `slowcat`, `struct`,
`mask`, `every`, `scale`, `sine`, `perlin`, `saw`.

### 2. Исполнение в Node — ДА

| Что | Результат |
| :--- | :--- |
| `mini('bd sd hh').queryArc(0, 4)` | 12 событий (3 × 4 такта) |
| `n('0 5 2 6').scale('c:minor')` | 4 ноты: C3, Ab3, Eb3, Bb3 |
| Партии `$NAME:` | собираются, опрашиваются, порядок сохраняется |
| 64 такта, 6 партий | **25 мс** (первый прогон с загрузкой — 13 мс) |
| 5 прогонов по 32 такта | 21 мс |

Производительности хватает с запасом: метрики v2 можно считать на каждом
итерационном цикле refine.

Свой парсер mini-нотации (`server/music/mini.js`) на этом фоне ограничен: он
разбирает 1–2 такта и не понимает `arrange`, `stack`, `cat/slowcat`, `<…>/n`,
`.slow/.fast`, `.mask`, `.struct`, `.every`. Расхождения с движком измерены:

| Паттерн | Наш парсер | Strudel |
| :--- | :--- | :--- |
| `bd*4, hh*8` (2 такта) | 24 события | 24 события ✓ |
| `bd sd hh` (2 такта) | 6 событий | 6 событий ✓ |
| `<0 5 2 6>/2` (2 такта) | 1 событие | 4 события ✗ |

Вывод: старый парсер годится для проверки «есть ли партия/лад/темп», новые
метрики прогрессии — только по событиям Strudel.

### 3. `arrange` с метками, `silence`, цепочками эффектов

`arrange([8, silence], [16, bassA], [16, bassB])` — секции раскладываются по
тактам: `silence` даёт **пустую** секцию, следующая начинается со своего такта.

| Секция | Такты | События |
| :--- | :--- | :--- |
| `silence` | 0–7 | 0 |
| `bassA` | 8–23 | есть |
| `bassB` | 24–39 | есть |
| за пределами arrange | 40+ | 0 |

Цепочка эффектов **после** `arrange` (`.gain(0.8)._pianoroll()`) таймлайн не
ломает. `silence` — не событие, а пустой паттерн: в метриках это «партия молчит».

### 4. Нотация гармонии

**Степени лада — единственный надёжный способ выразить гармонию.**

| Форма | Результат |
| :--- | :--- |
| `n("0 2 4").scale("c:minor")` | C3, Eb3, G3 ✓ |
| `n("0 2 4").scale("c:major")` | C3, E3, G3 ✓ |
| `chord("Am").voicing()` | A3, C4, E4, A4, C5 ✓ |
| `chord("Am7").voicing()` | ✓ |
| `chord("C").voicing()` | ✓ |
| `chord("A:min").voicing()` | **пусто** — `unknown chord "A,min"` ✗ |
| `chord("<C:min!4>")` | ✗ (тот же формат) |

Символ аккорда пишется **как в tonal**: `Am`, `Am7`, `C`, `F#m7b5` — через
двоеточие не принимается. Форма `"I V vi | IV"` — не Strudel вообще.

**Степень — это индекс ступени, а не нота.** В `c:minor` степени 0..6 дают
C D Eb F G Ab Bb, а степень 7 — тонику следующей октавы (C4). Трезвучие в
`c:minor` — это степени `0 2 4`.

### 5. `.scale()` и `setCpm`

**Имена ладов — только полные, одним словом.** Иначе результат пустой и
ошибка проходит мимо:

| Имя | Результат |
| :--- | :--- |
| `c:major`, `c:minor`, `c:dorian`, `c:phrygian`, `c:lydian`, `c:mixolydian` | ✓ |
| `c:ionian`, `c:aeolian`, `c:pentatonic`, `c:blues`, `c:chromatic` | ✓ |
| `c:maj`, `c:min` | **пусто** — `Scale name c maj is incomplete` ✗ |
| `c:harmonicminor` | **пусто** ✗ |
| `c:harmonic minor` | ✓ (с пробелом) |
| `c:minor pentatonic` | ✓ (с пробелом) |

Наш собственный `MODES` в `server/music/notes.js` использует `harmonicminor`,
`majpent`, `minpent` — эти имена **нельзя** класть в генерируемый код. В
компиляторе используется отдельный whitelist ладов.

`setCpm(bpm/4)` — рабочая форма, транспилятор её пропускает без ошибок.
В бандле нет отдельной функции `setCpm` (темп ставится через `cpm`/`cps`),
но синтаксис `setCpm(124/4)` — это то, что пишет генератор и что понимает
браузер.

## Прочие проверенные факты

**Автоматизация через сигналы работает** и попадает в значения событий:

| Выражение | Значения |
| :--- | :--- |
| `.gain(sine.slow(4).range(0.2, 0.8))` | 0.500, 0.650, 0.760, 0.800, 0.760, 0.650 |
| `.lpf(sine.slow(4).range(300, 3000))` | cutoff: 1650, 2325, 2819, 3000, … |
| `.gain(perlin.range(0.2, 0.8))` | 0.200, 0.265, 0.446, 0.512, … |

Сигнал `sine.slow(4).range(a,b)` сам по себе отдаёт константу (0.5) — он
раскрывается только в контексте параметра паттерна. **Это важно для метрики
автоматизации:** анализировать надо AST/значения событий, а не текст.

**Вариации партии работают**: `every(2, x => x.rev())`, `struct`,
`ply(2)`, `degradeBy(0.5)`, `sometimesBy(0.3, …)`, `chunk(4, …)`, `mask`,
`stack`, `cat`, `slowcat`, `rev`.

**`.off()` требует двух аргументов** — `.off(0.25, x => x.fast(2))`. Один
аргумент даёт `expects 2 inputs but got 1`. Для сдвига достаточно `.late()` /
`.early()` — они работают с одним числом.

**`/2` замедляет чередование, а `/n` внутри последовательности — другое дело.**
`n("<0 5 2 6>/2")` даёт 4 ноты по 2 такта (8 событий на 8 тактах, с
дубликатами в `whole`), `n("0 5 2 6/2")` — совсем другой ритм. Для аккорда на
2 такта правильнее `n("<0 5 2 6>").slow(2)`: 4 события, длительность 2 такта.

**Валидатор не запрещает нужные конструкции.** `staticValidate()` пропускает
и `arrange`, и стрелочные функции `x => x.rev()`; `parseParts()` видит партии
`["BASS", "DRUMS"]`, `getBpm()` даёт 124, `getKey()` — `c:minor`.

## Дополнение фазы 2: нотация, проверенная пробами

Отдельные приёмы проверены на живом движке (пробы фазы 2, выводы закреплены
тестами `tests/unit/compiler.test.js`).

**`.add(паттерн)` складывает значение в СТЕПЕННОЕ пространство, если стоит до
`.scale(key)`.** Это способ построить арпеджио, идущий по аккордам
прогрессии:

```
n("0 2 4").add(n("<0 5 3 4>").slow(2)).scale("c:minor")
```

Такт 0 — тоны аккорда i (C, Eb, G), такт 2 — тоны аккорда vi (Ab, C, Eb), такт
4 — аккорда iv (F, Ab, C). Три ноты на такт, аккорд меняется каждые
`barsPerChord` тактов. Порядок важен: `.add()` после `.scale()` ломает связь со
степенями лада.

**`.fast(n)` на базовом паттерне не трогает добавленный.** С
`n("0 2 4").fast(2).add(n("<0 5 3 4>").slow(2))` получаются 16-е ноты при смене
аккорда каждые 2 такта.

**`.struct()` ненадёжен, если длина ритма не совпадает с числом нот.**
`n("0 2 4").struct("x ~ x x")` даёт восемь событий с повторами и потерей
третьей ноты. Поэтому ритм мотива переводится в mini-строку собственным
образом: степени раскладываются по нажатиям (`x ~ x x` + `[0, 2, 4]` → `0 ~ 2 4`).

**`.oct(-1)` и `.add(-12)` после `.scale()` высоту не меняют.** Первый молча
ничего не делает, второй ругается `Can't do arithmetic on control pattern`.
Поэтому октавного сдвига у партий нет: `sub` отличается от `bass`
синтезатором (`sine` против `sawtooth`), а не регистром.

**`.scale(key)` нельзя применять к сэмпловым партиям.** Для `s("bd*4")` движок
пишет `[tonal] Invalid value format for 'scale'`. Лад применяется только к
партиям с нотами.

## Ограничения

- `sine.slow(n).range(a,b)` без контекста параметра даёт константу — при
  анализе «голого» сигнала получится ноль автоматизации.
- `chord()` с символами через двоеточие не работает — гармонию выражаем
  степенями.
- Имена ладов из `MODES` (`harmonicminor`, `majpent`, `minpent`) не годятся для
  генерируемого кода.
- Наш парсер mini-нотации расходится с движком на `slow`/`/n` — для метрик
  прогрессии источником истины служит Strudel.
- Октавного сдвига партий нет (см. выше) — бас и саб звучат в одном регистре.
