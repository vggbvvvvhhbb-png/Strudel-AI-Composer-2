Задача фазы 0: не поверить рисерчу, а проверить кодом, что нужно мини-студии для
звука: мастер-цепочка, офлайн-рендер, позиция, банки сэмплов, лимитер, autoplay.

регрессии пакета.

## H1 — как вставляется мастер-цепочка

Рисерч утверждал: публичного API нет, нужен перехват `connect`. В 1.3.0 хвост
мастер-шины superdough доступен через экспорт `getSuperdoughAudioController()`,
но сами узлы (`destinationGain`, `channelMerger`) — внутренние поля минифицированного
бандла. То есть это **работающий, но не документированный** хук.

Цепочка движка: `dough-processor (AudioWorklet)` / орбиты → StereoPanner →
ChannelSplitter → `channelMerger` → **`destinationGain`** → `ctx.destination`.

```js
// Мастер-цепочка студии: хвост шины движка перехватывается экспортным хуком.
strudel.setSuperdoughAudioController(null);   // сбросить синглтон-контроллер
strudel.setAudioContext(ctx);                 // контекст ставим ДО получения контроллера
await strudel.initAudio({ maxPolyphony: 64 }); // worklet-модули грузятся в ctx

const ctrl = strudel.getSuperdoughAudioController();
const tail = ctrl.output.destinationGain;     // GainNode перед destination

tail.disconnect();          // рвём прямой путь в ctx.destination
tail.connect(masterIn);     // и заводим его в нашу цепочку
masterIn.connect(ctx.destination);
```

| Замер (офлайн-рендер, стерео) | RMS | dBFS |
|---|---|---|
| baseline (цепочки нет) | 0.073035 | −22.729 |
| цепочка с gain 0.5 | 0.036518 | −28.750 |
| цепочка с gain 1.0 (bypass) | 0.073035 | −22.729 |

- отношение 0.5 → **0.500007** (цель 0.5 ±10 %);
- остаток bypass − baseline = **−∞ dB** (точно ноль, цель ≤ −40 dB).

Риски рецепта:

| Риск | Что делаем |
|---|---|
| `output.destinationGain` — приватное поле минифицированного бандла: может исчезнуть при обновлении | контрактный тест движка (`tests/unit/engine-contract.test.js`) ломает сборку при смене версии; в коде студии — проверка `ctrl?.output?.destinationGain` с запасным путём |
| контроллер — синглтон, привязанный к контексту на момент создания | `setSuperdoughAudioController(null)` **до** `setAudioContext(ctx)`, иначе контроллер остаётся со старым контекстом |
| worklet-модули superdough грузятся в каждый новый контекст заново | офлайн-рендер — в отдельном контексте; реалтайм-контекст создаётся один раз |
| баг в бандле 1.3.0: `!r instanceof OfflineAudioContext` (приоритет операторов) → `resume()` вызывается и для офлайн-контекста | на практике безвредно; зафиксировано здесь, чтобы не искать причину позже |

## H3 — офлайн-рендер

| Свойство | Значение |
|---|---|
| Детерминированность | два рендера: maxAbsDiff = 0, RMS(diff) = 0 |
| `renderPatternAudio` (официальный) | возвращает `undefined`, WAV-блоб 352 844 Б через `<a download>` |
| Побочный эффект официального рендера | **закрывает текущий `AudioContext`** (running → closed), глобальный контекст заменяется |
| AudioBuffer | перехватывается патчем `startRendering` — 88 200 кадров |

Официальная функция в живом приложении непригодна: она убивает аудиоконтекст.
Офлайн-рендер студии делается собственным кодом в отдельном `OfflineAudioContext`
(рендер-воркер) — тем же DSP-ядром.

Схема вызова события (из кода движка), по ней и строим свой рендер:

```js
const haps = pattern.queryArc(from, to, { _cps: cps }).sort((a, b) => a.whole.begin - b.whole.begin);
for (const hap of haps) {
  if (!hap.hasOnset()) continue;
  await strudel.superdough(hap.value, (hap.whole.begin - from) / cps, hap.duration / cps, cps, (hap.whole.begin - from) / cps);
}
```

## H5 — позиция

`scheduler.now()` отдаёт **циклы**, а не секунды. При cps = 0.5 разница с
`ctx.currentTime` плавала от −1.12 до −0.20 «цикла», а в секундах была
константой: `now()/cps − currentTime` = **−0.060 с**.

| Величина | Значение |
|---|---|
| `baseLatency` | 0.010 с |
| `outputLatency` | 0.040 с |
| `clock.duration` | 0.050 с |
| Смещение планировщика | −0.060 с |

Вывод: `scheduler.now()` пригоден, но требует перевода в секунды (`/cps`) и
вычитания задержек. Плейхед: `heardTime = ctx.currentTime − (baseLatency + outputLatency + masterLatency)`.

## H9 — лимитер

Встроенный в superdough `compressor` — это `DynamicsCompressorNode`.

| Устройство | Выход (вход 0 dBFS) | Перебор | Задержка |
|---|---|---|---|
| `DynamicsCompressorNode` (−3 dB, 20:1, knee 0, attack 1 мс) | −1.027 dBFS | **+1.973 dB** сверх порога | 6 мс (20 мс на ровном тоне) |
| наш `LookaheadLimiter` (потолок −1 dB, lookahead 5 мс) | −1.000 dBFS | **0.000 dB** | 5 мс |

Решение: встроенный компрессор как brickwall не используем, glue-компрессор и
лимитер — свои, в мастер-цепочке (`src/audio/dsp/comp.js`, `src/audio/dsp/limiter.js`).

## H2 — дакинг

Разбор бандла и паттерна:

| Метод | Что делает |
|---|---|
| `.duck(n)` | **алиас** `.duckorbit(n)` — оба пишут поле `duckorbit` |
| `.duckorbit(n)` | номер орбиты-жертвы (в superdough — `duckorbit`) |
| `.duckonset(t)` / `.duckons(t)` | момент начала дакинга (смещение в секундах) |
| `.duckattack(s)` | время атаки (минимум 2 мс) |
| `.duckdepth(d)` | глубина |

Ограничение движка: орбита-жертва должна **существовать**, иначе движок пишет
`duck target orbit N does not exist` и дакинга не будет. Значит партия-жертва
обязана иметь `.orbit(N)`.

Поведение (глубина, время) в браузере **не измерено** — это задача фазы 2/4.
Резервный путь (генерировать gain-огибающую в компиляторе) пока не строим.

## H12 — autoplay

В headless Chrome контекст стартует `running` во всех режимах: и с
`--autoplay-policy=no-user-gesture-required`, и без флага, и с
`document-user-activation-required`. Различить поведение не удалось — headless
не воспроизводит политику автовоспроизведения обычных браузеров.

`initAudioOnFirstClick()` ведёт себя корректно: до клика промис не разрешён,
после клика — разрешён, состояние `running`.

Вывод: риск «первый такт молчит» на реальных браузерах не снят измерением,
но и не опровергнут. Поэтому в фазе 2 закладываем прогрев: `initAudioOnFirstClick`
+ немой буфер + предзагрузка сэмплов до старта планировщика.

## DSP-ядро: сверка с эталоном

Эталон — `ffmpeg ebur128` (libebur128). Допуск приёмки: |ΔLUFS| ≤ 0.3,
|ΔdBTP| ≤ 0.3. Фикстуры — 48 кГц, стерео, float32 WAV.

> **Уточнение фазы 2 (D-038).** Громкость сверяется с ffmpeg, а true peak — с
> libebur128: ffmpeg меряет true peak ресемплером libswresample (до 192 кГц),
> а не фильтром приложения 2 стандарта, и на широкополосных фикстурах
> завышает пик до +0.7 дБ. Наш фильтр теперь совпадает с libebur128 до
> 0.001 дБ; в таблице ниже колонка «dBTP ref» — это libebur128.

| Фикстура | LUFS ref | LUFS наш | ΔLU | dBTP ref | dBTP наш | ΔdBTP |
|---|---|---|---|---|---|---|
| синус 1 кГц −20 dBFS | −20.00 | −19.99 | 0.01 | −20.00 | −20.00 | 0.00 |
| синус 1 кГц −26 dBFS | −26.00 | −25.99 | 0.01 | −26.00 | −26.00 | 0.00 |
| белый шум −18 dBFS | −16.60 | −16.64 | −0.04 | −13.38 | −13.38 | 0.00 |
| свип 100 Гц…8 кГц −12 dBFS | −9.20 | −9.18 | 0.02 | −11.98 | −11.98 | 0.00 |
| 12 кГц −3 dBFS (true peak) | 0.30 | 0.35 | 0.05 | −3.00 | −3.00 | 0.00 |
| 0.5 с сигнала + тишина | −11.50 | −11.54 | −0.04 | −10.00 | −10.00 | 0.00 |

Итог: |ΔLUFS| ≤ 0.05, |ΔdBTP| ≤ 0.01 — коридор выдержан с запасом.

Найденные при сверке ошибки (исправлены):

| Ошибка | Симптом | Решение |
|---|---|---|
| K-взвешивание по RBJ вместо ITU | расхождение 0.055 по b0 шелла | формулы Таблицы 2 ITU-R BS.1770-4 (совпадение 8.9e-16) |
| полифазный фильтр true peak без нормировки фаз | −12 дБ на выходе | сумма каждой фазы = 1 |
| фильтр true peak с дробной групповой задержкой | −0.42 dBTP против ffmpeg | 97 отсчётов, задержка 12 целых отсчётов |
| glue-компрессор: положительное «сжатие» | сигнал **усиливался** вместо ослабления | `targetReduction` возвращает отрицательные дБ |
| glue-компрессор: `−Infinity − −Infinity` на тишине | выход NaN, звук пропадал | явная ветка тишины, сброс огибающей |
| true peak: `const` переприсваивается | падение при первом вызове | `let` |
| **разбор вывода ffmpeg: true peak брался из покадрового `FTPK`** | `FTPK` — пара «текущее/максимум»; для файла с переходным в начале показывает уровень в конце, а не пик файла | true peak берётся из «True peak: Peak: …» в блоке Summary (D-038) |
| **фильтр true peak: своя АЧХ вместо стандартной** | расхождение с libebur128 до 0.7 дБ на широкополосных сигналах | фильтр заменён на алгоритм libebur128 (49 отсчётов, окно Ханнинга, 4×), совпадение 0.001 дБ (D-038) |
