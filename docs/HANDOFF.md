# HANDOFF — состояние проекта на конец сессии

*Обновлено 14 ноября 2026, сессия «скил-паки + LLM-планировщик + Baseline-0 + дорожка H»*

## Что сделано в этой сессии

Прошлая сессия оборвалась на середине: скил-карты были написаны, но machinery
(загрузчик, компилятор учебника, CI-гейт) — нет, не проверена и не закоммичена.
Эта сессия закрыла разрыв и довела до измеримого состояния.

### 1. Скил-паки стали работающей подсистемой

| кусок | где |
|---|---|
| Схема карты (Zod), разбор frontmatter без yaml-зависимости | `server/skills/schema.js`, `server/skills/loader.js` |
| Компилятор учебника (детерминированный, бюджет 3200 токенов) | `server/skills/compile.js` |
| Линтер примеров: dry-parse в headless-Strudel, guardrails, лад | `server/skills/lint.js` |
| CI-гейт `npm run check:skills` + доказательство | `scripts/check-skills.mjs`, `docs/evidence/skills/` |
| API карт и учебника | `GET /api/skills`, `GET /api/skills/:id`, `POST /api/skills/compile` |

### 2. LLM отвечает планом, а не кодом (спринт S3.2)

`server/ir/planner.js` + `server/ir/schema-json.js` + `POST /api/skills/plan`.
Учебник из карт → LLM (JSON по контракту) → Zod → IR → компилятор → код.
Ремонтный ретрай с текстом проблемы, бюджет вызовов, кэш по
(промт, версия учебника, зерно, версия схемы), запасной путь по правилам, если
модель недоступна. Мок-LLM отвечает настоящим IR — CI проверяет весь путь.

### 3. Baseline-0 заморожен (спринт S0.2)

`corpus/baseline0/`: 60 промтов (4 квадранта × 5 жанров × 3 плотности), сплит
36/12/12 по sha256 id, для каждого — план, код, хэши и символьный разбор.
`npm run check:baseline` ломает CI при правке корпуса. Средний символьный скор
корпуса — 85.1, lint-ошибок — 0.

### 4. Дорожка H: суждение работает

`server/routes/preference.js` (очередь пар, запись меток, надёжность
рецензента, экспорт, удаление) + страница `/tinder.html` (`src/tinder.js`):
рендер обоих вариантов в браузере тем же движком, выравнивание громкости
**только гейном**, случайная перестановка по каналам, каждая десятая пара —
повтор с переставленными сторонами.

## Следующие 3 действия

1. **Первые 10–20 человеческих пар.** Страница `/tinder.html` готова; нужен
   владелец: 20 пар ≈ 6 минут. Без этого H3 (корреляция символьного скора с
   человеком) и Taste Model невозможны — это главный блокер проекта.
2. **LLM-бюджет.** Планировщик умеет ≤2 вызова на compose, но лимиты в долларах
   не заданы: нужны числа «на трек», «на лучше», «суточно».
3. **Аудио-Baseline-0 и рендер-сервис.** Собрать 60 WAV с renderFingerprint
   (спайк R0: headless Chromium vs браузер) и решить, живёт ли рендер на том
   же GCP-хосте рядом со «швейкой» (A4).

## Блокеры

- **Метки.** Главный дефицит: человек должен сравнить треки между собой.
  Символьный скор остаётся гипотезой, пока это не случилось.
- **Лицензии сэмплов.** 42 сэмпла из 44 тянутся с GitHub-CDN, не вендорены,
  тексты лицензий не сверены (S1.C). Для публикации — блокер.
- **Домен.** sslip.io временный; свой DNS не настроен.
