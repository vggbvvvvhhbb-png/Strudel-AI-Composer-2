# HANDOFF — состояние проекта на конец сессии

*Обновлено 15 ноября 2026, сессия «Прорыв»: фазы A0, A, B, C закрыты (гейт A — 15/15, гейт B — 10/12 с двумя честными «нет данных», гейт C — L0 зелёный); фаза D сделана наполовину — мотив, фразировка и L1-метрики мелодии готовы, «разбор как учитель» ещё нет.*

## Где мы сейчас

Фазы **A0 (фундамент), A (помощник-агент), B (local-first) и C (100 дорожек
и опера) закрыты**. В фазе **D (мелодический мозг)** сделана первая половина:
движок мотивов, общая тема трека, фразировка A|A'|B|A'' и честные L1-метрики
мелодии (связность, развитие, каденция, разрешение, энтропия, диапазон).

Потолок в 12 партий снят: ключ `parts.roles` — идентификатор партии
(`VIOLIN_1`), роль стала атрибутом. Трек из **66 дорожек** собирается из
плана детерминированно (`src/music/expand.js`), рендерится локально без
клиппинга и проходит гейт L0.

Помощник — это настоящий агентный цикл «план → инструмент → наблюдение →
ответ» с SSE, деградацией без ключей, памятью разговора и панелью в студии.
Тяжёлое считается на машине владельца: локальный демон `local/` с очередью
на диске — задача переживает убийство процесса.

Гейт проекта — одна команда: `npm run gate` (13 шагов). Гейты фаз:
`npm run gate:a` (15/15) и `npm run gate:b` (10/12, две строки — «нет
данных»). Решения сессии: D-097…D-110.

Следующая фаза — **D: «разбор как учитель»** (готовый рефайн-цикл → compose)
и **E: sound hunter**.

## Что НЕ сделано и почему (честно)

1. **Разделение на стемы не измерено** — на этой машине нет `numpy`, `torch`,
   `demucs`. Демон честно показывает `analysis.available = false`. Нужно
   Python-окружение владельца: инструкция в `local/README.md`.
2. **«Бит-в-бит» для рендера не подтверждено** — локальный и серверный WAV
   различаются на 1 LSB в смеси осциллятора и сэмпла (D-104, E-019). Допуск
   проекта (maxAbsDiff ≤ 1e-4) соблюдён, `renderFingerprint` совпадает точно.
3. **Публикация заблокирована** — 2 банка сэмплов без подтверждённой лицензии
   (`dirt-samples`, `shabda:piano`), 219 имён. `npm run gate -- --release` —
   красные ворота. **Нужно решение владельца** (D-099, `docs/PARKING.md` §3).
4. **Выученная цель не принимается гейтом** — живых пар 10 (нужно 60),
   закрыто промптов 5 (нужно 50). Механика зелёная, данных не хватает.
5. **Полный проход гейта A с интернетом не измерен** — ключа `EXA_API_KEY` в
   репозитории нет. Измерена честная деградация.
6. **Цена LLM с реальным ключом не измерялась** — ключей нет; панель
   показывает «Цена не измерена», а не ноль (D-102).
7. **Два инструмента из таблицы гайда не реализованы:** `freesound_search`
   (фаза E) и `ab_eval` (нужен живой рецензент).
8. **Фронт не подключён к демону** — демон, маршруты и измерения готовы;
   кнопка «считать локально» в студии — это фаза F (UX).
9. **Оркестровая раскладка стала настоящей, но не «умной».** Голоса стоят в
   своих регистрах и играют **одну общую тему** (дивизи, своя фраза в каждой
   секции) — это закрывает половину пункта 9 старой версии. Не сделано:
   тема не знает гармонии (гармония по-прежнему строится из корней
   аккордов), и ни одного прослушивания человеком «до/после» не было —
   числа выше это измерители, а не оценка качества.
10. **Мастер по умолчанию не годится для оркестра** — порог −20 dBFS
    компрессора жмёт материал на 5 дБ (см. `docs/SESSION_REPORT.md` §1.4).
    В демо заданы оркестровые настройки; дефолт студии стоит поменять.

5. **Фаза E**: sound hunter (`freesound_search`, только CC0/CC-BY) и

## Правила, которые нельзя нарушать

- Тесты зелёные на каждом чекпоинте; `npm run gate` — одна команда.
- Ключи — только в env; `check:secrets` зелёный.
- `check:taste` не обходить; выученная цель не входит в скор до гейта людей.
- Каждый новый сэмпл/шрифт/датасет — запись в `docs/LICENSES.md`.
- Серверный GPU не покупаем (D-089). Локальные вычисления — можно (D-097).
- Не выдавать имитацию за агента: если тулз не вызывается по-настоящему —
  это чат с декорациями, гейт не пройден.
- «Нет данных» ≠ 0: оценка помечается оценкой, неизвестная цена говорится
  словами, а не нулём (D-102).
- Каждые ~4 часа: атомарные коммиты + `docs/SESSION_REPORT.md` + `docs/HANDOFF.md`.
