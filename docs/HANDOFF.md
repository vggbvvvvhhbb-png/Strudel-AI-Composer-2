# HANDOFF — состояние проекта на конец сессии

*Обновлено 14 ноября 2026, сессия «ждать пар, обучать модель»*

## Что сделано в этой сессии

Прошлая сессия закрыла «выученную цель» на уровне кода: пара рождается
вместе со своими признаками, модель обучается, но живых человеческих пар
было ноль. Эта сессия взяла направление владельца — **«ждать пар, обучать
модель»** — и сделала так, чтобы эти 6 минут в день не пропадали впустую.

Главное: **путь суждения был сломан, и владелец об этом не знал.** Страница
отдавала тишину и кривую громкость. Починка — в основе этого хода.

### 3. Что сделано для «6 минут в день»

* Фрагмент пары сокращён с 16 до 8 тактов (16 с на сторону): 20 пар ≈
  6–7 минут вместе с рендером, а не 20 минут.
* Очередь **продолжается**: сервер считает, где рецензент остановился, и
  предлагает новые промты (60 стратифицированных промтов корпуса
  Baseline-0: 4 квадранта × 5 жанров × 3 плотности).
* В строке прогресса видно покрытие: «12 / 20 · промтов 12/50» — это и есть
  приёмочный счётчик §7.2.
* Честная деградация: если сэмплы не загрузились, страница предупреждает и
  помечает метку `degraded` — такая метка сохраняется, но в обучение не
  идёт.

## Честный статус: модель обучена, но НЕ допущена

```
НЕ допущена в скор.
  — человеческих пар 0 < 60 — модель не используется
  — CV-accuracy — < 0.6
  — нижняя граница CI 0 не выше лучшей базовой линии
```

Это правильный ответ, а не сбой: символьный скор не проверен людьми,
значит, целью оптимизации он быть не может (§2.8). Прокси-пары размечены
самим символьным скором и учат модель воспроизводить его — по построению
тавтология, поэтому в вердикт они не входят никогда.

Доказательства: `docs/evidence/taste/gate.json`, `docs/evidence/taste/taste.json`,
`docs/TASTE.md`.

**Открыть `https://music.34.88.114.146.sslip.io/tinder.html` и судить 20 пар.**
Это ~6 минут. Метки сразу становятся обучающими примерами, а в строке
прогресса видно, сколько РАЗНЫХ промтов закрыто (нужно 50).

Что важно знать про этот путь:

* страница **не** требует регистрации и не пишет никаких персональных данных;
  удалить всё — одной командой (`DELETE /api/preference`);
* пара играется сама (A слева, B справа, порядок выпадает случайно),
  громкость выровнена гейном, метки скрыты;
* если треки прозвучали неполно (не грузились сэмплы), страница честно
  предупредит, и такая метка не попадёт в обучение — лучше не положиться на
  неё, чем отравить модель.

  Символьный скор остаётся гипотезой, пока это не случилось.
- **Лицензии сэмплов.** 42 сэмпла из 44 тянутся с GitHub-CDN, не вендорены,

  сервера, ни с машины (нужен взгляд владельца на DNS-записи).

## Команды запуска

```bash
npm install
npm test                     # 854 теста
npm run lint
npm run build
npm run dev                  # сервер + Vite

# Выученная цель:
npm run taste:train          # обучить на накопленных парах → docs/TASTE.md
npm run check:taste          # гейт механики → docs/evidence/taste/gate.json

# Очередь пар:
npm run check:prompts        # пул промтов совпадает с корпусом (по хэшу)
npm run queue:prompts        # пересобрать пул (осознанно, меняет файл)

# Скил-паки:
npm run check:skills         # гейт карт (+ docs/evidence/skills/)
npm run check:baseline       # заморозка Baseline-0 (+ docs/evidence/baseline/)
npm run baseline:build       # пересобрать корпус (осознанно, меняет манифест)
```

API: `GET /api/taste` (состояние), `POST /api/taste/train` (обучить),
`GET /api/taste/active` (какие пары судить дальше), `GET /api/preference/pairs`
(состав реестра), `GET /api/preference/stats` (счётчики, надёжность, покрытие
промтов), `DELETE /api/preference` (стереть все метки).
