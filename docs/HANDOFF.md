# HANDOFF — состояние проекта на конец сессии

*Обновлено 14 ноября 2026, сессия «выученная цель + реестр метрик»*

## Что сделано в этой сессии

Прошлая сессия закрыла скил-паки, LLM-планировщик, заморозку Baseline-0 и
дорожку H. Эта сессия взяла следующий кусок брифа v2 — **спринт S4.3
«выученная цель»** — и одновременно переделала то, что мешало её сделать.

Главная находка: **выученная цель была невозможна не из-за нехватки
меток, а из-за формы их записи.** Метка хранила только хэши двух треков
(«победил вот этот»). Хэш — идентификатор, а не признак: по двум хэшам
нельзя построить разность векторов, то есть обучать было нечем.

### 1. Рефакторинг: метрики и веса скора живут в одном реестре

`src/metrics/registry.js` — 43 метрики (id, единицы, диапазон, цель,
источник, версия), критерии символьного скора, критерии аудио-блока и веса
смешивания v1/v2/аудио. У каждого веса теперь есть явное
`validated: false` — «не проверено на людях» (бриф §2.8).

До этого веса были размазаны по трём модулям, а комментарий в
`audio-score.js` описывал формулу `v1·0.5 + v2·0.3 + аудио·0.2`, которой в
коде не было (код считал `0.48 / 0.32 / 0.2`). Числа не изменились,
комментарий приведён в соответствие, формула зафиксирована тестом.

`src/metrics/extract.js` — единственное место, где отчёт превращается в
числа по id метрик: объявление и измерение больше не могут разъехаться.

### 2. Прорыв: пара рождается вместе со своими признаками

| кусок | где |
|---|---|
| Реестр пар: IR обеих сторон, хэши, промпт, зерно | `server/preference/ledger.js` |
| Метка с аудио-признаками (L0) каждой стороны | `server/routes/preference.js`, `src/tinder.js` |
| Признаки L0+L1 (42 шт.) + стандартизация | `src/taste/features.js` |
| Bradley–Terry (градиентный спуск, L2, без случайности) | `src/taste/model.js` |
| Leave-prompt-out CV, базовые линии, Уилсон, вердикт | `src/taste/cv.js` |
| Активный отбор пар (неуверенность + страты) | `src/taste/active.js` |
| Сборка выборки + прокси-пары best-of-N | `server/taste/dataset.js` |
| Обучение, сохранение, описание модели | `server/taste/service.js` |
| API: отчёт / обучение / активный отбор | `server/routes/taste.js` → `/api/taste` |
| Офлайн-обучение и гейт | `scripts/train-taste.mjs`, `scripts/check-taste.mjs` |

Страница «Тиндер» теперь меряет обе стороны тем же DSP-ядром, что и
студия (LUFS, true peak, crest, клиппинг) и отправляет числа с меткой.
Сквозной путь **пара → метка → обучающий вектор → веса** закрыт тестом.

## Честный статус: модель обучена, но НЕ допущена

`npm run taste:train` отрабатывает целиком: 60 прокси-пар из Baseline-0,
14 из 42 весов ненулевые, точность на прокси-данных 0.92. Но вердикт:

```
НЕ допущена в скор.
  — человеческих пар 0 < 60 — модель не используется
  — CV-accuracy — < 0.6
  — нет базовых линий для сравнения
```

Это правильный ответ, а не сбой: символьный скор не проверен людьми,
значит, целью оптимизации он быть не может (§2.8). Прокси-пары размечены
самим символьным скором и учат модель воспроизводить его — по построению
тавтология, поэтому в вердикт они не входят никогда.

Доказательства: `docs/evidence/taste/gate.json`, `docs/evidence/taste/taste.json`,
`docs/TASTE.md`.

   теперь сразу даёт обучающие примеры. Нужен владелец: 20 пар ≈ 6 минут.
   После этого `npm run taste:train` покажет честные CV-accuracy и

3. **Аудио-Baseline-0 и рендер-сервис.** Собрать 60 WAV с renderFingerprint
   (спайк R0: headless Chromium vs браузер) и решить, живёт ли рендер на
   том же GCP-хосте рядом со «швейкой» (A4).

## Блокеры

- **Метки.** Главный дефицит: человек должен сравнивать треки между собой.
  Символьный скор остаётся гипотезой, пока это не случилось.
- **Лицензии сэмплов.** 42 сэмпла из 44 тянутся с GitHub-CDN, не вендорены,
  тексты лицензий не сверены (S1.C). Для публикации — блокер.
- **Домен.** sslip.io временный; свой DNS не настроен.

## Команды запуска

```bash
npm install
npm test                     # 842 теста
npm run lint
npm run build
npm run dev                  # сервер + Vite

# Выученная цель:
npm run taste:train          # обучить на накопленных парах → docs/TASTE.md
npm run check:taste          # гейт механики → docs/evidence/taste/gate.json

# Скил-паки:
npm run check:skills         # гейт карт (+ docs/evidence/skills/)
```

API: `GET /api/taste` (состояние), `POST /api/taste/train` (обучить),
`GET /api/taste/active` (какие пары судить дальше), `GET /api/preference/pairs`
(состав реестра).
